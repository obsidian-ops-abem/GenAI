# Jev Engineering 実践ガイド — 分割と失敗モード

> **「Jev は賢い if 文」。テキストを作る→LLM・選ぶ/スコア/yes-no→Jev・正確なルール→コードの3バケット。confidence は RLCD で較正されており、アクション毎に間違いのコストで閾値をスケール（元に戻せないものは高バー+人間確認）。失敗モード6種（文字通りに読む・計算不能・日付はテキスト・context rot・世界知識なし・state は敵対扱いでない）と正直なスコアカード（67.8%・自己運営・「ハルシネーション不能」の狭さ）が検証の要。**

## 05_Jev Engineering（@0xMovez版）からの主な差分

| 項目 | 本記事の追加知見 |
|---|---|
| **RLCD** | 較正の根拠。人間の選好でなく結果に対して確率を最適化 → confidence は集合的に意味を持つ |
| **confidence 設計** | グローバル閾値でなく**アクション毎にコストでスケール**。読取専用=低バー・不可逆=高バー+人間確認 |
| **失敗モード6種** | 文字通り読む・計算不能・日付=テキスト・context rot・世界知識なし・**state は敵対扱いでない（プロンプトインジェクション面）** |
| **スコアカード** | 67.8%（自己評価・コンセンサスラベル問題・「ハルシネーション不能」は構成による主張） |
| **プロンプトインジェクション** | 「ユーザー制御コンテンツが state に入るなら、それが脅威モデル」 |
| **カスケードの経済** | 最大の節約は「安いモデル」でなく**モデルを完全にスキップする純コード分岐** |

## 核心 — 分割とカスケード

- **3バケット**: テキスト生成→LLM ／ 選択・スコア・yes-no→Jev ／ 正確なルール→コード
- **カスケード**: 1分岐は純コード（モデル不触）・1分岐は専門 LLM・1分岐は人間。**「Jev はどのリクエストがフロンティアモデルに値するかを決める」**
- **全部一度に聞く**: 質問は並行実行。10問目は時間ほぼゼロ。**LLM で培った「安い呼び出し→フォローアップ」の直感が反転**。13問バッチ=1問ずつより12倍安く10倍速い

## 実務ディテール

- **Choice は最大255オプション**。全リストを渡す。**必ず other を追加**
- **Noul の数字そのものが信念**（confidence フィールドなし）
- **モデル版をピン**。jev-latest は無言で移動し閾値調整が全部崩れる
- **制限**: state+全質問 64K / state+最長1質問 32K トークン
- **診断**: probabilities がフラット = state から選択肢が区別できない（criteria が悪い）
- **ログ**: 全決定でモデル版・確率・confidence を記録（$0.0004/件の層でログが薄いと事故が再構成不能）

## 失敗モード6種（検証の要）

1. **文字通りに読む** — 否定・暗黙条件は額面通り。「本当はこう意味だった」と説明したら、それが instructions の欠けた半分
2. **計算機でない** — カウント誤差は対象サイズで増大。コードで反復・1項目1 Noul
3. **日付はテキスト** — 先後・間隔・ウィンドウはコードへ。抽出は列挙 Choice
4. **Context rot** — 不要材料で state が埋まると精度低下。**コードでフィルタしてから送る**
5. **世界知識なし** — state の組み立て側が Jev の世界を決める。**弱いソース=悪い材料の well-calibrated な判断**
6. **state は敵対扱いでない** — 分類を自己主張するテキストが回答を動かせる。ユーザー制御コンテンツ=脅威モデル

## 正直なスコアカード

- **67.8%**（ミッドティアフロンティア同率・トップより下）だが**コスト1/200・レイテンシ1/50**
- その列は精度でない（2フロンティアモデルのコンセンサス一致度・TypeSafe 自身が明記）
- 自己運営・独立再現なし。**自分のトラフィックで評価してから信用するな**
- 「ハルシネーション不能」= スキーマ外の値を返せないだけ。**誤った妥当な値は返せる**
- 価格は補助金の可能性あり
