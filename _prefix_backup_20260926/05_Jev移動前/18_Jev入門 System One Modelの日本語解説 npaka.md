# Jev 入門 — System One Model の日本語解説（npaka）

> **Jev の日本語入門決定版。「非構造化された状態を入力し、型付きの確率的な判断を出力」。高速性の源泉は parallel sampler（複数判断の並列出力）+ 新アーキテクチャ + RLCD。DOOM を10Hz・約7ドル/時で操作。「型が正しい」と「判断が正しい」は別。日本からの利用ではNW遅延に注意。「スマートなif文」として全所に配置。**

## 技術的ポイント

- **「unstructured state in, typed probabilistic decisions out」** — TypeSafe の公式表現
- **parallel sampler**: LLM はトークン毎の逐次生成。Jev は**複数の判断を並列出力**（敵がいる？0.96 / 攻撃？0.84 / 左？0.13 / 右？0.81）。これが高速性の設計上の源泉
- **DOOM デモ**: 10Hz（平均100ms/判断）・**約7ドル/時**。画面でなく**構造化データ+テキスト**のゲーム状態を渡す
- **応用範囲**: 100ms 前後はモーター直接のサーボ制御には向かないが、**対象物選択・行動切替・異常検出など数Hz〜10Hzの上位判断**は可能
- **日本からの注意**: 70ms は米国西海岸測定。**クラウド API では NW 遅延が加わる**

## LLM との違い（Structured Outputs との本質差）

- LLM は「生成 → 必要なら出力形式を制約」。Jev は**最初から型付き判断+確率を出力する設計**
- **「ハルシネーションしない」= 定義済み型・選択肢以外を出力しない、の意**。「判断を間違えない」ではない
- **「型が正しい」ことと「判断が正しい」ことは別**

## 組み合わせ

- ユーザー → Agent →（Jev: 高速分類・判断 ／ LLM: 推論・文章・コード生成）
- **「スマートなif文」（smart if-statements）** — AI 版 if 文としてアプリの各所に配置
