# スマホから PC の codex と cc をリモート操作

> **「スマホ側にめっちゃ優しい設計。今ではこれが Mac 上の Agent をリモート操作するデイリーの手段」** — codex/cc の公式モバイルアプリのサブスク・ネットワーク・切替の煩雑さを、ターミナルマルチプレクサ + ssh で回避するハック。

出典: [[39_スマホからPCのcodexとccをリモート操作（出典）]]（Bysir @hi_bysir, 2026-07-30。本文はユーザー提供クリップから再構成）

## 一行で

**Herdr（ターミナルマルチプレクサ + Agent First）＋ Termius ＋ ssh** で、スマホから Mac 上の codex / Claude Code をリモート操作する構成。公式モバイルアプリのサブスク・ネットワーク・2アプリ切替の問題を、既存のターミナルインフラで解決する。

## 解く問題

codex と cc（Claude Code）にはそれぞれモバイルアプリがあるが:

- **アカウントのサブスクリプション** の問題で使いづらい
- **ネットワーク** の問題で使いづらい（※モバイルアプリがクラウド経由で動く設計だと、ローカルの PC 上の Agent を直接触れない・遅延・認証壁などの制約が生じる）
- **2つのアプリを切り替える必要がある**（codex 用・cc 用でアプリが分かれている）

公式アプリでなく「1つのアプリ（Termius）で全部済ませたい」という動機。

## 構成（4要素）

| 役割 | ツール | 役割 |
|---|---|---|
| PC 側 | **Herdr** | ターミナルマルチプレクサ + Agent First（herdr.dev） |
| スマホ側 | **Termius** | 無料・使いやすい ssh クライアント |
| 接続 | **ssh** | `ssh [IPアドレス]` のみ。同 LAN 環境前提 |
| スリープ防止 | **Amphetamine** | 蓋を閉じても Mac を起こさない |

- **公網に公開する場合**: 公網サーバー + **FRP**（Fast Reverse Proxy — NAT/ファイアウォール越えでローカルポートを外部にトンネルする OSS。家庭内 LAN の Mac を外出先のスマホから叩くために使う）
- **前提**: Mac でリモートログイン（ssh デーモン）を有効化しておく

## 核心: ターミナルマルチプレクサが「スマホに優しい」

Herdr のようなターミナルマルチプレクサは、**セッションが PC 側で生き続ける**ため、スマホ側の接続が切れても Agent の実行は継続する。これが「スマホ側に優しい」設計の本質。公式モバイルアプリがクライアント側の状態に縛られるのに対し、ssh + マルチプレクサは**PC をサーバー、スマホを薄いターミナル**にする。

## コメント欄の代替案

> [!note] 代替ツールの言及あり
> コメント欄で **Paseo**（全ターミナル対応）、**網易UU**（商業プロジェクト依存・課金リスク）等の代替が挙がっている。@hi_bysir 自身は「UU も大多数には良いが、商業プロジェクト依存でいつ課金が始まるか分からない」と OSS/自前ルート（Herdr + ssh + FRP）を選んだ理由を語る。この「商業サービス依存を避けてローカルファースト／OSS で構成する」姿勢は、本ボルトの運用思想（ローカル Markdown + git、[[03_Obsidianのおすすめ機能と選ぶ理由]] の指摘）とも通底する。

## ライセンス・状況

- **Herdr**: herdr.dev（ターミナルマルチプレクサ + Agent First）
- **Termius**: 無料枠ありの ssh クライアント
- **FRP**: OSS（Fast Reverse Proxy）
- **Amphetamine**: macOS 用スリープ防止（無料）
