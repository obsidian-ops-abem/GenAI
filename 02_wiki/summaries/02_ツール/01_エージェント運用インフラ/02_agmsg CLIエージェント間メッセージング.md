# agmsg —— CLI AI エージェント間メッセージング

> **「コミュニティが agmsg に強い輪郭を与えてくれている」** — Claude Code / Codex / opencode 等、CLI で動く AI エージェント間でメッセージをやり取りする OSS。v1.1.12 は機能追加でなく**コミュニティ主導の成熟**を示す。v1.4.x で **Jev（System One 決定モデル）をエージェントチームの同僚にする ext-tool** と**1通に100問まとめ投げ**が可能に。

## 一行で

CLI で動く AI エージェント（Claude Code / Codex / opencode 等）間でメッセージをやり取りするための OSS。エージェント間連携のインフラで、コミュニティによる周辺ツール（可視化・監視）が独立に育つエコシステムを形成。

## v1.4.x（2026-09）— Jev をチームの同僚に・1通に100問

### v1.4.0: jev ext-tool（Jev をエージェントチームのメンバーに）
- **jev-agent 宛てのメッセージがそのまま Jev API 呼び出しになる** ext-tool
- 安全フックのログ889件を30件ずつ Jev に判定（妥当/過剰/保留）する運用を実証
- 「0.2〜0.3秒で答えるツールに、返事を受け取るために1ターン払うのは高い」が当時の課題

### v1.4.2: 1通に何十問も入る（測定結果つき）
**測定**（公開データセット SST-2[2択]・Banking77[77択]・計測全体で $0.0096=1セント）:
| 条件 | 結果 |
|---|---|
| 2択 100問を1通 | **0.50秒**・正解率99〜100% |
| 77択 45問を1通 | 3秒・正解率87%（39/45）・確信度0.7未満7行を「人が見るべき候補」と名指し |
| 77択 100問 | 断られる（「分けて送って」の1行・**料金なし**・0.3秒） |
| 上限の正体 | 問数でなく**1回の入力合計 ≈6.5万トークン**（選択肢説明を毎問繰り返すため77択は45問で頭打ち） |

**直した3つの問題**:
1. **2問以上なら1問1行で返す**（従来は答えが1行に全部連結し、呼び側が再分解させられた）
2. **壊れた答えが1問あっても全体を失敗にしない**（従来は100問中1問の崩れで100問分が全損。その1問だけ error にし残り99問は返す）
3. **送りすぎたら理由と対処を言う**（従来は「unexpected HTTP 400」のみ）

- **使い方の目安**（jev の USAGE.md に記載）: 選択肢2〜5択なら100問1通でよい／数十択なら40問前後から始め断られたら半分に／断られても無料なので「大きめに投げて半分に」で損しない／**error の行だけ拾って再送すれば残りは捨てなくていい**
- **1.4.2で最も変わった点**: 1ターンのコストは同じでも**その1ターンで受け取れる答えが100個に**。「この50件、jev に聞いといて」というその場のまとめ投げがもとが取れる。889件は従来30通→**9通**
- **教訓**: 「記録に残した形が、そのまま実装の仕様になる」——計測時の記録（OpenRouter の400本文は内側の形だけ残っていた）を仕様通りに読み、実APIで初めて不正になるバグを見つけた。安全面: 返事の1行に改行・制御文字・タブを混ぜない（ターミナル/ログ直流のため）

> **Jev との接続**: [[05_Jev Engineering 決定と生成を分離するSystem One]]・[[08_Jevは誰のためのモデルか 汎用Decision Model]]。「判断は Jev・生成は LLM」を agmsg チームに組み込む実例。ccc（[[03_ccc関連事例調査 ボルト内の同じアプローチ]]）の査に相当する「軽量判断役」を Jev が担う構成
