# LangChain エージェント・エンジニアリング・プラットフォーム

> [!info] 出典
> [langchain-ai/langchain](https://github.com/langchain-ai/langchain)（GitHub、MITライセンス）
> 詳細メタデータ: [[14_langchain-ai langchain（出典）]]

LLM（大規模言語モデル）を使ったアプリケーションを組むための「エージェント・エンジニアリング・プラットフォーム」を名乗るフレームワーク。[[04_Langflow ビジュアルAIワークフロービルダー]] がGUIでグラフを組む道具だったのに対し、こちらは**コードでエージェント・ワークフローを組むための基盤ライブラリ群**という位置づけ。

## 主要機能

- **相互運用可能なコンポーネント連携** — 異なるシステムやデータソースを統合し、LLMの機能を拡張する
- **リアルタイムデータ拡張** — 多様な社内外データソース・システムへのアクセスを、豊富なインテグレーション群を通じて提供する
- **モデルの柔軟な選択** — 抽象化層を通じて異なるLLMプロバイダー間を切り替えられ、チームが実験しながら最適なモデルを選べる

## アーキテクチャ（3パッケージ構成）

| パッケージ | 役割 |
|---|---|
| **LangChain Core** | モデル・埋め込み・ベクトルストアなどの標準インターフェースを提供する基盤層 |
| **Deep Agents** | 計画立案・サブエージェント・ファイルシステムアクセスなどを組み込んだ上位レベルパッケージ |
| **LangGraph** | 複雑なエージェントワークフローを構築するための低レベルオーケストレーションフレームワーク |

`LangGraph`という名前の通り、[[01_Graph Engineering エージェントを行列から解放する]] で説明されていたノード・エッジ・分岐・合流といったグラフ概念を、コードで直接組むためのレイヤーに当たる。

## 使い方

```bash
pip install langchain
```

`init_chat_model` でOpenAIなど任意のプロバイダーのモデルを初期化し、`invoke` メソッドで入力を処理する、という流れが基本形。

## 対象ユーザー

LLM統合を素早くプロトタイピングしたい開発チーム、マルチエージェントシステムを構築したい企業、RAG（検索拡張生成）やエンタープライズAI導入を検討する組織。

## 所感・関連

- Langflow（ビジュアル・GUI志向）と LangChain（コード・ライブラリ志向）は、同じ「エージェント/ワークフロー構築」という課題への異なるアプローチ。実際、LangflowはLangChainのコンポーネントを内部で利用していることが多く、対立というより「同じエコシステムの別レイヤー」に近い
- `LangGraph`という名称が象徴的で、[[01_Graph Engineering エージェントを行列から解放する]] の議論（ノード＝境界の明確な作業単位、エッジ＝実データが渡る依存関係、6トポロジー）を実装する際の具体的なコード基盤の一つとして位置づけられそう
- READMEベースの紹介が中心で、実際の学習コストや、バージョン間の破壊的変更の多さ（LangChainはAPIが頻繁に変わることで知られる）といった実務上の注意点は今回未確認
