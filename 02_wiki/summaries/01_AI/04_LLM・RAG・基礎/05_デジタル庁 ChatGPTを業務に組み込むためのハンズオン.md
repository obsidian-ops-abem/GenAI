# デジタル庁「ChatGPTを業務に組み込むためのハンズオン」

> **「100回の会議より、1回のAPI callの方が理解が進む。まずは試してみよう」** — 政府機関による、非エンジニア向け GPT API 実践ガイドの決定版。

出典: [[26_デジタル庁 ChatGPTを業務に組み込むためのハンズオン（出典）]]（デジタル庁 Fact&Data Unit / 大杉直也、2023-06-26、全46ページ）

---

## 一行で

デジタル庁が2023年6月に公開した、**ChatGPT 的処理を業務システムに組み込むための実践ハンズオン**。GPT API の仕組みからプロンプト設計、他システム連携、従来NLPとの使い分けまで、要求分析段階での「どのくらい実現できそうか」推定を主眼に置く。

## 資料の骨格

スライドは次の5層で構成される:

1. **マインドセット** — アイデアの価値は検証してみないとわからない。「作って終わりではないが、作らないと話にならないのでさっさと作る」
2. **APIの基礎** — ChatGPT vs GPT API、token とコスト、messages（system/user/assistant）構成
3. **プロンプトTips** — コツ、候補だし・step by step、デモ、逐条解説の system 埋め込み、試行錯誤手順
4. **発展: 組み込み方** — 入出力書き換え、他システムとの組み合わせパターン、従来NLPとの使い分け
5. **将来** — 複数APIの統合（Boosting的アプローチ）

## 特に重要な視点

### ① ブラックボックスを相手にする（p.10）
- 入出力の対から性質を判断するしかない。**完全制御は難しいので、許容できるユースケースを探し出す**
- 「どのくらい実現できそうか」には**濃淡がある**（全くできない〜ほぼできる）
- → 要求分析段階でこの濃淡を推定し、（１）どこで（２）だれに（３）どのように使わせるか、の解像度を上げる

### ② API は「状態をもたない」（p.20）
会話履歴を毎回入力に含める。token 上限により保持履歴に限界（当時32k）。

### ③ messages の3役と自由度（p.15–24）
- `system`=役割、`user`=入力、`assistant`=出力（**直接書き換え可能** → few-shot の容易さと脆弱性の両方）
- 同じ「要約」でも、system に文章を入れるか user に入れるかで**プログラムの性質が変わる**（Aについて答えるくん vs 文章要約くん）

### ④ 逐条解説の system 埋め込み（p.30–33）
GPT の知識は古く（2021/9まで）誤りも反映されるため、新規法令はプロンプトに直接書き込む。token 超過は**GPT自ら項目ごとに要約**させて解決（508字→204字）。文節ごとの要約は「参照元回答可・人間の見落とし確認・精度向上」の3利点。

> 「作る際に専門家が必要」＆「AIが専門家を上回ることはない」

### ⑤ プロンプト開発手順（p.34）
1. まず **GPT3.5** で
2. system/user を書き挙動確認
3. 直示が必要なら assistant
4. 不満なら GPT4 へ。**GPT4でダメならプロンプトが悪いか課題が難しすぎる（だいたい前者）**
5. GPT4でOKなら 3.5 でも動くよう平易化を検討

### ⑥ 従来NLPとの使い分け（p.42）
GPTを使うまでもない処理（形態素解析など）は**従来型が品質安定・高速・安価**。辞書整備は依然重要。住所の表記ゆれなどは形態素解析だけでは困難なケースも。

## 発展: GPT の入出力書き換え（p.38）

品質安定化・不適切コンテンツ対策:
- **入力書き換え**: ユーザ入力に制約を付与（「(第N条によると、の形式で回答)」）
- **出力書き換え**: json指定して一部キーのみ返却、jsonでなければエラー

→ プロンプトインジェクション対策にも有効（限界は prptinj.net で体験可能）

## 所感・現在からの距離（2026年視点）

- 2023年6月時点の資料で、**「GPT4で32k」「3.5で0.002USD/1k token」**等の数値は古い
- しかし**「完全制御は諦め、許容できるユースケースを探す」「要求分析段階で濃淡を推定する」「GPTを使うまでもない処理は従来型」**という判断軸は、モデルが進化しても変わらず有効
- 「assistant の直接書き換え」「入出力書き換えによるインジェクション対策」は、現在のエージェント設計でも基本として生きている
- 3年後のPixelRAG [[04_PixelRAG スクショで検索するRAG]] のような「視覚ベース」へ進んだが、本資料の「他システム出力をGPTで要約」「GPTでフォーマット成型してDB登録」という組み合わせパターンは原型として参照価値が高い
