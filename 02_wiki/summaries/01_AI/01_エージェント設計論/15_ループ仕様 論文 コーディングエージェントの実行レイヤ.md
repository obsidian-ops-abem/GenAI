# ループ仕様 —— コーディングエージェントのための実行レイヤ

## 一行で

コーディングエージェントのための**「欠けていた実行レイヤ」**として **ループ仕様（loop spec）** を定義した CS 論文（arXiv 2607.00038）。ループ仕様は4要素（明示的トリガー・検証可能目標・停止ルール・メモリ）をバンドルし、**手動のステップバイステッププロンプティングを境界付き自己修正ループで置き換える**。実世界のループの70%が決定論的チェッカー・明示的終端状態・メイカー・クリティック分割で「自律ゾーン」で実行される。

## 核心: 手動プロンプティング → 境界付き自己修正ループ

ほとんどの開発者は今でも、実行のあらゆるステップでコーディングエージェントを**手動でプロンプト**している。本フレームワークはこれを:
- **境界付き自己修正エージェントループ**で置き換える
- 人間の手取り足取りを**自動化された検証ラダー**で置き換える

## ループ仕様の4要素

| 要素 | 内容 |
|---|---|
| **明示的トリガー**（explicit trigger） | ループをいつ開始するかの明示的条件 |
| **検証可能目標**（verifiable goal） | done を機械が判定できる形で定義 |
| **停止ルール**（stopping rule） | いつループを終了するかの明示的ルール |
| **メモリ**（memory） | ループ間で状態を保持 |

この4つがバンドルされることで、手動のステップバイステッププロンプティングが不要になる。

## 自律ゾーンでの実行（70%）

実世界のループの70%が以下を用いて**自律ゾーン**（人間の介入なし）で実行される:
- **決定論的チェッカー**（deterministic checkers）
- **明示的な終端状態**（explicit terminal states）
- **メイカー・クリティック分割**（maker-critic split: 生成と批評を分離）

## 本ボルト内の位置付け

Loop Engineering 系の**学術的定式化**。本ボルトの Loop 系ノート群に「ループ仕様」という概念の正式名を与える:

- **4要素（トリガー・検証可能目標・停止ルール・メモリ）** は、[[09_Loop Engineering Claude,GPT 実戦で効くもの]]（実戦5原則: done 定義・接地検証器・階層的終了・コスト規律・不可逆前チェック）を学術的に定式化。特に「**検証可能目標**」「**停止ルール**」は done 定義・階層的終了の正式概念化
- **「メイカー・クリティック分割」** は、[[14_自己レビューエージェントのGraph設計 Anthropicメソッド]]（見えない2人のレビューア・judge を先に構築）や [[12_Graph Engineering with Claude 14-Step roadmap]]（step09 verifier 3パターン: adversarial/diverse/judge）の「生成と検証の分離」の学術名
- **「決定論的チェッカー」** は、[[14_自己レビューエージェントのGraph設計 Anthropicメソッド]]（退屈なチェックを決定論化・コストで配置）・[[13_Graph Architectへの20ステップ5フェーズ]]（Step 6 全ノードが LLM でない・関数で検証）と同思想の定式化
- **「境界付き自己修正ループ」** は、[[02_24時間自走する自律型AIエージェントの設計図]]（状態機械優先・7原則）・[[01_エージェントファクトリの作り方 ビルダーズガイド]]（検証ステーション）が実務で主張した「境界付き」を学術的に表現

- **@biektive の「モデルに自分で採点させるのをやめろ」** は、本ボルト全体の verifier 系思想（[[09_]]・[[14_]]・[[12_]]）の核心を一句で表現。**外部の検証器・決定論的チェッカーがループの信頼性の源泉**
