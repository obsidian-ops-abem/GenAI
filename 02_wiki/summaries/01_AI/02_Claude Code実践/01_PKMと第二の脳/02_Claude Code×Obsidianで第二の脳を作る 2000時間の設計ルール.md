## 5分セットアップ（3ステップ）

1. Obsidian インストール（obsidian.md、無料・商用OK）
2. Vault フォルダで `claude` 起動（`cd ~/Documents/MyVault && claude`）
3. **キックオフプロンプト**:

```text
ObsidianをAIとの情報管理に使いたい。
僕の目標・タスク・好みについて質問して、
すり合わせが終わったらVaultのフォルダ構造と
CLAUDE.mdを提案・作成して。
```

→ Claude Code が**逆質問**し、答えるだけで フォルダ構造／CLAUDE.md／タグ規則／テンプレート／安全ルール／既存ノート整理を自動生成。コード不要。

## CLAUDE.md = 脳の設計図（核心）

起動時に毎回読まれる指示書。第二の脳の質はここで決まる。

### 書くべき5要素

1. フォルダ構造の説明
2. タグ規則（kebab-case 統一等）
3. ノートテンプレート
4. リンク規則
5. **安全ルール**（元ノート消さない・削除は提案のみ）

### フォルダ構成 2パターン

**① 知識ベース型**（初心者向け）: `CLAUDE.md` / `books/` / `articles/` / `wiki/`
**② プロジェクト型**: `CLAUDE.md` + `docs/{daily,research}`

> **制約を厳密にするほどAIの出力が上がる**（AIエージェント100体以上で確信）

## 6つの運用パターン

| # | パターン | プロンプト例 |
|---|---|---|
| ① | **知識検索** | 「プロジェクトXでリスクに言及したメモだけ抜き出して要約して」— **意味ベース検索** |
| ② | **自動整理** | 「Clippings内のノートを内容ごとに振り分けて」 |
| ③ | **自動タグ付け** | 「今週更新したノートに規則沿いのタグを」 |
| ④ | **リンク自動生成** | 「関連しそうな既存ノートを `[[リンク]]` して」 |
| ⑤ | **週次レビュー** | 「停滞プロジェクトにフラグを立てて」 |
| ⑥ | **過去の自分と対話** | 「1年前、転職について何を考えていた？」 |

まず①②③から。

## 2,000時間の設計ルール7つ（本文で最も価値がある部分）

### 散らかりを構造で防ぐ（①〜④）
特に③が効果的 → CLAUDE.md に1行: **「保存前に既存ノートと重複がないか確認して」**。AIが自動重複チェック。

### AIが迷わず動ける命名と棚卸し（⑤〜⑦）

- **⑤ プレフィックスで種別統一**: `feedback_` / `project_` / `reference_` / `user_` → **AIの検索が段違いに速くなる**
- **⑥ ノート冒頭にメタ情報**（名前・説明・種別）→ AIが「開く前に関連性判断」、全ノート読まなくて済む
- **⑦ 月次棚卸し**: 「完了済み・古い情報を整理。削除候補は一覧で提案だけ」→ **「捨てる」まで仕組み化できたら情報管理の上位1%**

## 安全に使う3つの注意点

AIはファイルの移動・削除・書き換えができる。**消失リスクはゼロではない。**

1. **バックアップ絶対** — Vault を Git 管理（「変更前に保存して」と指示）／クラウド（iCloud/Dropbox）／初回は丸ごとコピー
2. **CLAUDE.md の安全ルール3行**:
   ```markdown
   - 元のノートは絶対に削除しない
   - 整理は「移動」のみ。削除は「提案」だけ
   - 大規模変更前にGitで現在状態を保存
   ```
3. **「小さく試してから一括」が鉄則** — まず2〜3ファイルでテスト→意図通り確認→範囲拡大。20万円案件を1時間完遂するチームでも省略しない

## 上級オプション（シンプル版で十分）

- **MCP連携** — タグ・バックリンクを直接操作（プラグイン2つ＋コマンド）。**体感でシンプル版が8割カバー**
- **Claudianプラグイン** — Obsidian 内に Claude Code 統合、ターミナル不要（Claude有料プラン＋BRAT）

> **結論：シンプル版で十分。まずはターミナルで `claude` と打つところから。**
