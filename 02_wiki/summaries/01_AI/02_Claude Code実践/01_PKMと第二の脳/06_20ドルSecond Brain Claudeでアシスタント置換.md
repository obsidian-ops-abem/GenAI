# $20 Second Brain — Claude でアシスタント置換

> **月$2000のアシスタントを$20の Claude＋第二の脳で置換。raw/wiki/output の3フォルダ＋CLAUDE.md のアーキテクチャ。毎朝7時の自動巡回・writing-style.md による文体学習・プロジェクト毎フォルダ・記憶の累積。「セッションをリセットするのでなく累積する」ことで1年後に追い抜けない差が生まれる。**

## 一行で

@imryven による「Claude ＋第二の脳」の実践ガイド。月$2000のパートアシスタントを$20の Claude で置換する設計。`raw/` `wiki/` `output/` の3フォルダ＋`CLAUDE.md` の最小アーキテクチャで、リサーチ・執筆・プロジェクト管理・記憶を「リセットでなく累積」させる。本ボルトの運用ルールとほぼ同じ構成。

## アーキテクチャ（3フォルダ＋1ファイル）

| 要素 | 役割 |
|---|---|
| **raw/** | 全てのソースを最初に置く。記事・文字起こし・PDF・ボイスメモ・スクショ。不変・編集不可。ground truth |
| **wiki/** | Claude が raw を構造化記事に変換。clean・linked・相互参照。**Claude がここから思考する**。人間が読み・モデルが書く |
| **output/** | wiki をソースに完成成果物。プレゼン・レポート・ドキュメント |
| **CLAUDE.md**（ルート） | プロンプトでなく「その人の完全な姿」。誰・どう考える・何を作る・どこで詰まる・どう話してほしい。毎セッション読込 |

## 4つの置換パターン

### 1. リサーチ・分析
raw にソースを置き「読んで主要概念を抽出→wiki記事作成→既存ページへリンク→矛盾を旗」のプロンプト。1ソースが10-15ページに波及。「リサーチが消えず累積する」

### 2. 執筆・コンテンツ
`writing-style.md` に文体分析（文のリズム・語彙・避ける表現・段落開閉パターン）を保存。Claude は執筆前にこれを読み、あなたの文体を模倣。「AI っぽくなく自分の声」

### 3. プロジェクト管理
プロジェクト毎に `Inputs/Process/Outputs/Feedback` の4フォルダ＋`CLAUDE.md`。Claude は関連するものだけを見て、全生活でなく1プロジェクトに集中

### 4. リセットしない記憶
- 全 Claude 回答が wiki の新ページとして帰档
- 探索が累積・矛盾は日付付きで旗・パターンが蓄積
- **毎朝7時の自動巡回**：vault 全体を歩き・新規ノートを古いものへリンク・古いものを旗・3行サマリ（昨晩何が変わったか/今日何要注意か/何が矛盾として旗されたか）

## 累積の複利（時間スケール）

| 経過 | 変化 |
|---|---|
| 1か月 | セッション間で文脈を失わなくなる |
| 3か月 | 6週前に考えたことを vault が3つの関連アイデアと接続して surfaced |
| 6か月 | 毎日ゼロからの人との差が埋められなくなる |
| 1年 | graph view が数百ノードの地図。「第二の精神」 |

「1月に構築した人は12月には全く違うレベルで動く。賢いからでなく、リセットをやめ累積し始めたから」

## 正直な部分
アシスタントは onboarding に2週間かかったが、第二の脳は初日夜に理解した。忘れず・疲れず・新プロジェクトで再 onboarding 不要。モデルを変えても同じフォルダを指すだけ。

## 所感

本ボルトの運用ルールとほぼ同じ構成（raw-sources/wiki/output 相当＋CLAUDE.md）なので、非常に親和性が高い。違いは本ポストが「writing-style.md で文体学習」「毎朝7時の自動巡回と3行サマリ」を実装している点。特に毎朝巡回は [[14_Memory Engineer]] の「忘却ポリシー/保守」に対応する実務パターン。ただし「累積」を無条件に肯定する点は [[05_ULTIMATE SECOND BRAIN]] の「2000ノート超劣化」と [[14_Memory Engineer]] の「more memory が agent を悪化させる」で警告される通り、本ボルトの `99_to_delete/` のような忘却経路が必須。「$20 vs $2000」の対比は鮮烈だが、onboarding 不要性の主張はやや楽観的（アシスタントの文脈理解は異なる種類）。
