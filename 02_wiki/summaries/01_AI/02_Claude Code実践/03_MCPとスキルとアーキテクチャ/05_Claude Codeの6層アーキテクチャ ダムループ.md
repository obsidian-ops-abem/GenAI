# Claude Code の6層アーキテクチャと「ダムループ」

> **Claude Code は CLI でなく6層システム。モデルはループ内の1ノードに過ぎず、ループ自体は意図的にシングルスレッドの「ダムループ」。全インテリジェンスは周囲のレイヤー（ハーネス）にある。コンテキストは95%到達で要約でなく構造化抽出、マルチエージェントは worktree 隔離。**

出典: [[58_Claude Code 6層アーキテクチャ（出典）]]（@DailyDoseOfDS_ 日本語訳 / 参照元 Avi Chawla @_avichawla 2026-05-02。本文はクリップ全文＋コメントを使用）

## 一行で

Claude Code の内部構造を6層（入力 / 知識 / 実行 / 統合 / マルチエージェント / 観測可能性）で図解し、中心のマスターエージェントループが「意図的にダムなシングルスレッド」で全インテリジェンスがハーネス側にあることを示す解説。

## 6層（核心）

| # | 層 | 役割 | 要点 |
|---|---|---|---|
| 1 | **入力** | セッション管理・権限ゲーティング・YAML信頼ティア | モデルに到達する前に処理 |
| 2 | **知識** | スキルレジストリ・コンテキストコンプレッサー・タスクグラフ・クロスセッションメモリ | **ウェイトの外でハーネスの知性が生きる場所** |
| 3 | **実行** | ツール毎の型付きハンドラーレジストリ（bash/read/write/grep/glob/revert）・ストリーミング並行・プロンプトキャッシュ（約10%コスト） | ツールディスパッチ |
| 4 | **統合** | MCPランタイム（FS/git/カスタム）・ツールは内向き登録・メモリは agent_memory.md へ外向き永続化 | 外部サーバー接続 |
| 5 | **マルチエージェント** | サブエージェント + エージェントチーム（**最も過小評価**） | 2レベルの並列性 |
| 6 | **観測可能性** | ライフサイクルフック付きイベントバス・バックグラウンドエグゼキューター | 完全な監査トレイル |

## コンテキストコンプレッサー（層2の核心）

- コンテキストウィンドウが**約95%到達**で作動する**5層カスケード**
- ChatGPTのように会話を要約するのではなく、**ファイルパス・コードスニペット・エラーヒストリーへ構造化抽出**を実行しつつ冗長ツール出力を剪定
- 目標: コンテキストを小さくするのでなく**使用可能に保つ**こと

> @DevCalledFede（コメント）: /compact は自由形式指示を受け付けるので、閾値発火前に何を残すか操れる。サブエージェントは自身のウィンドウで動くので、大きな読みがメインに触れない
>
> @aditya_sarade14（コメント）: 「95% → 要約でなく構造化抽出」は多くの解説が飛ばす部分。自分のエージェントツール構築で痛学。**plain summarizing は本当に重要なファイルパスとエラー履歴を失う。pruning beats summarizing**

## マルチエージェント層（層5）— 2レベルの並列性

### サブエージェント
- セッション内の軽量ワーカー。独自コンテキストウィンドウ
- 焦点を絞ったタスク（コードベース検索・ファイルツリー探索）→ 結果を親に返す
- **互いに通信不可・サブエージェント生成不可**。厳格な親子階層

### エージェントチーム
- 1セッションがチームリーダー → 独立チームメンバー生成
- 各メンバー = 独自コンテキストウィンドウを持つ**完全な Claude Code インスタンス**
- リーダーがタスクをサブタスクに分解・割当・進捗監視
- 調整2メカニズム: **共有タスクリスト（ディスク上 JSON）** + **ピアツーピアメッセージングのメールボックス**
- 各メンバーは **git worktree 分離**（独自ブランチの別ワーキングディレクトリ・同一リポジトリ履歴）
  - コードベース重複部分への書き込みでもファイル競合なし
  - 変更のない worktree は自動クリーンアップ。変更あるものはマージ前・人間レビュー用に永続化

## マスターエージェントループ（中心・ダムループ）

- 6層の中心。コンテキスト組み立て → モデル呼出 → ツールリクエスト受領 → 実行 → 結果フィードバック → 繰り返し。各イテレーション = 1ターン
- **意図的にシングルスレッド**。全インテリジェンスは周囲のレイヤーにあり、ループロジックにない
- Anthropic はこれを**「ダムループ」**と呼ぶ: モデルが推論し、ハーネスが仲介する

- **@lfrodriguesit**: だから「より良いモデルを使う」はポイントを外す。**エージェントアーキテクチャが競争優位になりつつある**
