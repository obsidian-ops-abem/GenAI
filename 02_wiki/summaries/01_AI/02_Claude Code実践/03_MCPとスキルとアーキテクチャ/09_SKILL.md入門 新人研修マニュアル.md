# SKILL.md 入門 — 新人研修マニュアル

## 一行で

@futatabi_rojode による SKILL.md の初心者向け完全解説。SKILL.md を「新人スタッフに渡す引き継ぎマニュアル」と捉え、プログラミング知識不要の Markdown で書けることを示す。必須項目は2つだけ・3段階の lazy load 机制・4つのつまずきポイントまで網羅。[[01_agent-skill-creator ワークフローをAIスキル化]] の手前の「そもそも SKILL.md とは」を埋める入門編。

## SKILL.md の正体

- **コードでなく Markdown**：見出し・箇条書き・手順を並べるだけ。ブログ記事やメモと同じ感覚
- **エンジニア専用でない**：議事録要約・定型文作成・データ整理等の日常業務こそ効く
- **新人に渡す引き継ぎマニュアル**：AI に「こういう場面ではこの手順で」と渡しておくと、その場面が来たときだけ AI が読みに行く。普段は閉じたままなので**コンテキストを圧迫しない**

## 必須項目は2つだけ（frontmatter）

| 項目 | 制約 | 内容 |
|---|---|---|
| **name** | 64文字以内・小文字/数字/ハイフンのみ・「claude」「anthropic」不可 | スキル名 |
| **description** | 1024文字以内 | **「何をするか」＋「いつ使うべきか」の両方**が必須 |

### description の良し悪し（核心）

- △ 惜しい：「請求書を処理する」→「いつ使うか」が足りず AI が呼び出しを見逃す
- ○ 良い：「請求書PDFから金額・日付・取引先名を抽出する。請求書やPDFの数値抽出について聞かれたときに使う」

**「何をするか」と「いつ使うか」の2点セット**を意識するだけで精度が上がる。

## AI が SKILL を見つける3段階（lazy load 机制）

| 段階 | 読込タイミング | トークン消費 |
|---|---|---|
| **1. 名前＋説明** | 常に（起動時） | 1つ約100トークン |
| **2. 本文（手順）** | 呼び出されたときだけ | 5000トークン未満目安 |
| **3. 追加ファイル/スクリプト** | 必要になったときだけ | 使わなければ0 |

→ **棚にしまった取扱説明書**。存在するだけでは場所を取らず、開いたページだけ読む。

## ファイル構成

```
invoice-reader/
├── SKILL.md          ← 必須
├── scripts/          ← 任意
│   └── extract.py
├── references/       ← 任意
│   └── format-guide.md
└── assets/           ← 任意（テンプレート等）
```

SKILL.md 1ファイルだけでも立派に機能。慣れたら scripts/references/assets を少しずつ追加。

## 使える3つの場所

| 場所 | 方法 | 備考 |
|---|---|---|
| **claude.ai** | 設定の Features から ZIP アップロード | Pro/Max/Team/Enterprise・コード実行有効必須・自分専用 |
| **Claude Code** | フォルダを置くだけ | 自分用は `~/.claude/skills/`・プロジェクト用は `.claude/skills/` |
| **Claude API** | `skill_id` 指定で呼出 | コード実行ツールと組み合わせ・開発者向け |

**3つは自動接続されていない**。claude.ai の SKILL が Claude Code でそのまま使えるわけでない。使いたい場所毎に用意が必要。

## つまずきやすい4ポイント

1. **description を「何をするか」だけで終わらせる** → 「いつ使うか」も必須
2. **name に紛らわしい文字** → 大文字/アンダースコア/スペースはエラー。小文字＋ハイフンだけ
3. **知らない人の SKILL をそのまま使う** → 信頼できない配布元は意図しない操作のリスク。自分作成/公式から
4. **本文に詰め込みすぎ** → 本文は500行程度目安。詳細は references/ の別ファイルへ（必要なときだけ読込）

## 今日からできる最初の一歩

1. 「毎回同じ手順でやっている単純作業」を1つ思い浮かべる
2. フォルダを作る（例: `meeting-notes/`）
3. `SKILL.md` に name と description を書く
4. 普段の手順を箇条書きで書き出す
5. `.claude/skills/` に置く（Claude Code の場合）

保存や公開の手続き不要。あなたのフォルダにあなた専用の手順書が1つ増えるだけ。

## 所感

「新人研修マニュアル」という比喩が SKILL.md の本質をうまく捉える。特に「3段階の lazy load」は、なぜ SKILL をたくさん用意しても負担にならないか（段階1は1つ約100トークン）を説明し、[[08_Claudeを会社にする 42スキルの組織図]] の42スキルが成立する理由を裏付ける。description の「何をするか＋いつ使うか」は [[10_マルチエージェントでナレッジグラフ構築]] の「description と instructions の最適化に最も時間を使う」と同じ原理。本ボルトの運用ルール（CLAUDE.md）は1つの巨大な procedural memory だが、作業毎に SKILL.md に分割すれば description ベースの lazy load でコンテキスト節約になる可能性。入門記事だが実務的濃度が高い。
