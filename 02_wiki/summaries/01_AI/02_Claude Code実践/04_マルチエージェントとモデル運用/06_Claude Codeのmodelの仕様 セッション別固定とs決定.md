# Claude Codeの `/model` の仕様 — セッション別固定と `s` 決定

> **`/model` の通常選択は「今後新しく起動するセッションの既定モデル」を変える。個々のセッションだけモデルを固定したい場合は、モデル選択時に `s` で決定するか、起動時に `--model` オプションを使う。**

## 一行で

@oikon48 による Claude Code `/model` の挙動共有。並列で複数セッションを開いている場合、通常の `/model` 選択は「既存セッションへの即時影響」ではなく「以後新規に起動するセッションの既定モデル」を変える（リプライで訂正・確定）。**個別セッションだけモデルを固定したいときは `s` キーでの決定、または起動時の `--model` オプションを使う**。

## 挙動の詳細

- 通常の `/model` からのモデル変更は、**今後新しく起動するセッションの既定モデル**を変える（元ポストの「並列セッションに影響する」という表現は、リプライでの訂正を経てこの意味に確定した）
- **そのセッションだけモデルを固定したい場合**:
  - `/model` でモデル選択時に **`s` で決定**する
  - 起動時に **`--model` オプション**を指定する（例: `claude --model fable`）
  - いずれも他の Claude Code セッションには影響しない
- `claude --model fable` は 200K コンテキストの fable が起動する。**1M コンテキストを明示するには `claude --model fable[1m]`** が必要、という指摘に対し、投稿者が手元検証: `claude --model fable` でも実際には1Mコンテキストで起動し、`claude --model fable[1m]` はむしろ Claude Code が起動しなかった（**リプライ間で食い違いがあり、本投稿時点のバージョンでの挙動として鵜呑みにせず自身の環境で確認が要る**）

## リプライから見えるユースケース

- worktreeで並列セッションを開いている際、通常の `/model` 変更が「探索用に割り当てたhaikuセッション」まで意図せず巻き込みコスト増になった事例（`s` 決定で回避）
- 複数プロジェクト・複数タブを並行運用している場合ほど、セッション限定指定（`s` または `--model`）の価値が高い
