# CLINEに全部賭けろ — コーディングエージェント時代のプログラマ

> **Cline 型エージェントは「暴走列車」のように人間を伺わず高速で試行錯誤する。その速さが魔法でありパンドラの箱。人間の判断がボトルネックになる世界で、プログラマはナビゲータに、ドメイン記述力が核心スキルになる。**

出典: [[55_CLINEに全部賭けろ（出典）]]（mizchi @mizchi, 2025-02-26, Zenn。本文はクリップ全文を使用）

---

## 一行で

mizchi が Cline（Roo Code）を2ヶ月使い込み、「強い実行権限 + 圧倒的な試行錯誤速度」がもたらす体験の変質を、具体例（dig / HM型推論）とプログラマのスキル論を通じて語る宣言的エッセイ。

## Cline が先行ツールと違う理由

- **Copilot / Cursor** は人間の意思決定を尊重する消極的ナビゲータ（Copilot は `Math.<Tab>` の拡張止まり）
- **Cline** は「暴走列車」。最初の指示以外は人間を伺わず、強い（危険な）実行権限で試行錯呠サイクルを回す
- この「人間を待たない速さ」こそが Cline だけが到達した世界。中毒性がある
- 情報の非対称性が解けるとAIのコーディング力が観測できるほど上がる（単に情報不足だっただけ）

## 得意なことをやらせる（dig 関数の例）

- JSON から型推論付きでデータ抽出する dig 関数 → **15分で700行・17テスト全通過**
- AIが得意な条件: 外部参照がない / 技術ドメインに閉じる / モックが作りやすい / 既存実装がありそう
- **手数こそが一番大事**。その手数で人間はすでに勝てないフェーズに達している
- 人間の判断がボトルネック。モックデータでテストを通させる＝仕様をテストで表現する技術が問われる

## 難しいことをやらせる（HM型推論の例）

- 型なしJSON → HM型推論 → zod バリデータ構築を指示
- **ユーザー側の洞察が必須**: JSONで何が表現できるか / HM型推論とは何か / 抽出構造のJSON表現 / HM型推論のJSON適用の意味
- 自分が理解していないものを実装するには「結果から逆算される内部構造への直感」という高度な思考が必要。「プログラマでない人がプログラマに仕事を頼む時の感覚」

## ドライバー席を譲る（ペアプロの役割交代）

- Cline = ドライバー、人間 = ナビゲータ
- 人間は「Clineが得意そうな領域か（数学・アルゴリズム・ライブラリ）」を判断して振る
- タスク成功率7割 × 品質到達率7割 ≒ 使えるコードが出る確率は半分
- 戦略: Clineに得意領域をやらせ → 自分がリファクタリングしてモジュール化 → 繰り返し

## 苦手なこと: コンテキスト保持

- 「PoCを1ファイルに限定」or「参照ライブラリを明示」で運用（コンテキストが暗黙だと参照解決が苦手）
- Memory Bank / MCP / Agentic RAG は苦肉の策。**コンテキストウィンドウ拡大 vs サマリ生成、どちらが生き残るか現時点で読めない**（コストと相談して逐次選ぶ）

## AI時代のプログラマに必要な3能力

1. **コンテキストを記述する能力** — 適切なモジュール分割・境界づけられたコンテキスト抽出
2. **ドメインを記述する能力** — ユビキタス言語・DDD・ドメインエキスパートとしての抽象化
3. **AIの性能に対する直感**

`.clinerules`（Cline版の CLAUDE.md）に大量の指示を書き、それを自分の能力に合わせて構築できるのがプログラミング・ドメインエキスパートの価値。汎用プロンプトでは限界。加えて短期的能力: コスト圧縮のためのコンテキスト圧縮 + AIのミスを手動補正するエージェントとしての役割。

## プログラミング言語適性

- 向く: TypeScript / C# / Python（高水準・学習量大・静的型付けで実行前型チェック）
- 静的型付けの有無は**ループを回す速度に直結**（JSよりTSが成功率段違い）
- 向かない: Rust / Haskell（コンパイラ制約が厳しいと人間エキスパートの助けなしにパス困難）
- AIは「どんな指示を与えても実装を歪めてテストを通そうとする」＝ジュニアエンジニアの仕草

## なぜパンドラの箱か（セキュリティ）

- Cline は環境情報取得のため様々なコマンドを直接実行したがる（サンドボックス外）
- Auto Approver（許可リスト）はあるが、**人間がボトルネックと自覚すると確認が緩くなる**。サボって `-A(--allow-all)` しがち
- mizchi は deno の実行時パーミッション（`--allow-net` 等）で抵抗。Cline が行き着く先のホットテーマは**コンテナセキュリティと WebAssembly Sandbox** と予想

## vs プログラマ不要論

- プログラマは「コードを書く作業員」でなく「ドメインを抽象して構成要素を分解・再構築する思考訓練を受けた専門家」
- 高度なAIは自分の鏡。**AIから引き出せる性能は自分の能力に比例**。デバッグ難易度はむしろ上がっている
- プログラマの職業は終わらない。ただ変わるだけ（Tim O'Reilly / Steve Yegge 引用）
- ただし専門家のサンクコスト・バイアスで楽観しすぎも危険（翻訳職消滅の生々しさを引用）
- 今はハイプサイクル頂点 → 幻滅期が来る。**勝負はその後**: Cline型コーディングが整備され万人に開放されたとき適応している側だけが生き残る。生産性給与競争、あるいはAI管理パイプライン設計をコアスキルに
