# Claude Code 計画と実行を分けるワークフロー

> [!info] 出典
> SON([@S0N_IA](https://x.com/S0N_IA)) 2026-07-30 投稿
> [元記事](https://x.com/S0N_IA/status/2082312273700258243)
> 詳細メタデータ: [[18_Claude Code 計画と実行を分けるワークフロー（出典）]]

Claude Code でコーディングする際、**「計画（プランニング）」と「実行（コード編集）」を明確に分ける**ことで、手戻りを減らし精度を上げる実践的ワークフローを解説した投稿。

## 核心アイデア：Plan と Execute の分離

Claude Code に最初から「実装して」と頼むと、方針が固まらないまま書き始めてしまい、後で大きく作り直すハメになりがち。これを防ぐため、**計画フェーズと実行フェーズを意識的に切り離す**。

| フェーズ | 役割 | Claude Code への指示 |
|---|---|---|
| **Plan（計画）** | やるべきこと・方針・対象ファイルを整理 | 「まだコードを書かず、計画だけ立てて」 |
| **Execute（実行）** | 承認した計画に従って実際に編集 | 「この計画に沿って実装して」 |

## ワークフロー（手順）

```
1. 要件を伝え、Plan（計画）だけ出させる
   → 「コードは書かず、どう進めるか計画を立てて」
2. 計画をレビューし、必要なら修正指示
   → 見落としや方針のズレをここで潰す
3. 計画に OK を出す
4. 承認済み計画に基づいて Execute（実装）させる
5. 実装結果を確認 → 問題あれば計画に戻って軌道修正
```

### なぜ効くのか

- **Plan 段階で手戻りコストが低い** — コードを書く前なので、方針変更が一瞬で済む
- **Execute は「承認済みの道筋」をなぞるだけ** — ブレずに進み、ミスが減る
- **認知負荷が下がる** — 人間も「何を作るか」と「どう書くか」を別フェーズで考えられる

## Plan モードを活用するコツ

| コツ | 内容 |
|---|---|
| **「まだ書くな」と明示** | 「計画だけ」「コードは書かないで」と指示しないと、Claude は実装まで走りがち |
| **対象ファイルを列挙させる** | どのファイルを触るかを Plan 段階で出させると、影響範囲が先に見える |
| **小さく分ける** | 大きな機能も「Plan → Execute」のサイクルを細かく回すと精度が上がる |
| **実行後も計画を参照** | Execute 後の確認・テストも、Plan を基準にすると抜け漏れに気づきやすい |

## まとめ

- Claude Code は**「計画」と「実行」を分ける**だけで劇的に使いやすくなる
- まず「計画だけ立てさせる」→ レビュー →「承認した計画で実装させる」の2段階
- **Plan 段階でズレを潰す**のが、手戻り回避の最大のカギ
- 認知負荷も下がり、人間にもAIにも優しいワークフロー
