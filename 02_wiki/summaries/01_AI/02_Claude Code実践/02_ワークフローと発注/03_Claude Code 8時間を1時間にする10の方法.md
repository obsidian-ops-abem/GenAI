# Claude Code 8時間を1時間にする10の方法

> [!info] 出典
> Ashwin([@0xCodila](https://x.com/0xCodila)) 2026-07-22 投稿
> [元記事](https://x.com/0xCodila/status/2079597821511020996)
> 詳細メタデータ: [[19_Claude Code 8時間を1時間にする10の方法（出典）]]

Claude Code を実務で使い込み、**「8時間かかっていた作業を1時間に圧縮した」**という Ashwin 氏の10の Tips 集。単発のプロンプト技法ではなく、ワークフロー・設定・運用の最適化が中心。

## 10の方法（一覧）

| # | 方法 | ポイント |
|---|---|---|
| 1 | **CLAUDE.md に運用ルールを書く** | プロジェクトの前提・コーディング規約・禁止事項を毎回渡さずに済む。Claude Code が自動で読む「永続的コンテキスト」 |
| 2 | **サブエージェントに任せる** | 探索・検索・検証などの定型作業はサブエージェント（サブタスク）に切り出し、本体は設計・判断に集中 |
| 3 | **plan モードを活用する** | いきなり実装せず、まず計画だけ出させてレビュー → 承認後に実行。手戻りが激減（→ [[02_Claude Code 計画と実行を分けるワークフロー]]） |
| 4 | **小さくコミット・頻繁に確認** | 大きく進める前にこまめに検証。失敗も小さい単位で気づける |
| 5 | **明確で具体的な指示** | 「いい感じに」ではなく、対象ファイル・期待する挙動・制約を明示する |
| 6 | **コンテキストを整理して渡す** | 関連ファイル・エラーログ・要件をまとめて提示。推測させない |
| 7 | **MCP で外部ツールを直結** | DB・ドキュメント・Issue 管理などを Claude Code 内に持ち込み、往復をなくす（→ [[02_Claude Code開発者ボリス推奨 MCPサーバー8選]]） |
| 8 | **反復作業はコマンド化・Skill化** | 毎回やる手順は Skill/コマンドにして再利用（→ [[01_Agent Skillsを作る完全プロンプト]]） |
| 9 | **結果を検証する手段を渡す** | テスト実行・ビルド・ブラウザ確認など、Claude が自分で正しさを確かめられる環境を用意 |
| 10 | **失敗から学ばせて改善** | うまくいかなかった手順・プロンプトを記録し、CLAUDE.md や Skill に反映して継続改善 |

## 共通する思想

記事全体を貫くのは次の3つの原則（ボリスの3原則とも重なる）：

- **コンテキストを"外に出す"** — 毎回説明する内容は CLAUDE.md・Skill・MCP に。チャットには書かない
- **人間は判断、AIは実行** — 計画と検証は人間が、定形作業は AI が。役割を分ける
- **ループを回して改善** — 一発勝負せず、試して良かったものを仕組みに定着させる

## まとめ

- 劇的な時短の鍵は**「個別プロンプト」ではなく「ワークフローの仕組み化」**
- 中核は **CLAUDE.md ＋ サブエージェント ＋ plan モード ＋ MCP/Skill ＋ 検証手段**
- 人間は計画と検証に集中し、反復作業は AI に任せる構造を作るのが本質
