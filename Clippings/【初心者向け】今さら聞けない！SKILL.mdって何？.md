# SKILL.mdって結局なに？──「新人研修マニュアル」だと思えば、中学生でも今日から書けます

「SKILL.md」という言葉、見たことはあっても「なんだか難しそう」「プログラミングが得意な人のものでしょ？」と、そっと閉じてしまっていませんか。

結論から言うと、それは誤解です。SKILL.mdの正体は、コードの塊ではなく「新人スタッフに渡す1枚の引き継ぎマニュアル」に近いもの。読めるのはMarkdownという、ただの文章の書き方だけ。今日はその中身を、できるだけ噛み砕いてお伝えします。

【この記事でわかること】 ・SKILL.mdが「結局何なのか」をひとことで ・書くために最低限必要な、たった2つの項目 ・AIがSKILLを見つけて使うまでの3段階のしくみ ・どこで使えるのか（[claude.ai](https://claude.ai/)／Claude Code／API） ・今日からできる、最初の一歩

## そもそも、なぜSKILL.mdが必要なの？

たとえば毎回AIに「議事録を要約して」と頼むとき、あなたは無意識にこんな指示を毎回書き足していませんか。「決定事項は箇条書きで」「担当者名は太字で」「次回までのタスクは最後にまとめて」——。

この“毎回の指示出し”を1回だけ書いてSKILL.mdに保存しておけば、次からは「議事録を要約して」の一言だけで、AIが自動的にあなたの好みの手順を思い出して動いてくれます。SKILL.mdは、いわば「毎回繰り返す指示を、1回書いたら使い回せる形にしたもの」です。

メールの返信、週報のフォーマット、経費精算のチェック手順——「毎回同じことを言っている」と感じる作業があるなら、それはすでにSKILL.mdの候補です。一度言語化してしまえば、その後はずっと楽になります。

## 誤解①「プログラミングの知識がいる」は、実は違います

SKILL.mdは、プログラミング言語で書くものではありません。使うのはMarkdown。見出しをつけて、箇条書きにして、手順を並べる——ブログ記事やメモを書くのと同じ感覚です。

「AIに新しい仕事を1つ覚えてもらうための、手順書を作る」。それだけだと思ってもらって大丈夫です。

## 誤解②「エンジニアや専門職の人だけのもの」も、実は違います

SKILL.mdは、もともとClaude Codeというプログラミング支援ツールの現場でよく使われてきた経緯もあり、「開発者向けの機能」というイメージを持たれがちです。

けれど実際には、claude.aiの設定画面からZIPファイルをアップロードするだけで使える窓口も用意されています（プランや条件は後述します）。日々の議事録の要約や、定型文の作成、データ整理といった「エンジニアではない人の日常業務」こそ、SKILL.mdが効いてくる場面です。

## SKILL.mdの正体は「新人に渡す、1枚の引き継ぎマニュアル」

会社に新しいスタッフが入ってきたとき、いきなり全業務を丸暗記させたりはしませんよね。「この作業のときは、この手順で」というマニュアルを渡して、必要なときに開いてもらう。

SKILL.mdはまさにこれです。AI（Claude）に「こういう場面では、この手順で対応してね」という手順書を渡しておくと、実際にその場面が来たときだけ、AIがその手順書を開いて読みにいきます。普段は閉じたままなので、AIの頭の中（コンテキスト）を圧迫することもありません。

## 最低限必要なのは、たった2つの項目だけ

SKILL.mdの一番上には、frontmatterと呼ばれる短い自己紹介欄を書きます。必須なのは、たったの2つです。

■ name（名前） ・64文字以内 ・使えるのは小文字・数字・ハイフンのみ ・「claude」「anthropic」という単語は使用不可

■ description（説明） ・1024文字以内 ・「これは何をするものか」と「いつ使うべきか」の両方を必ず書く

たとえば「請求書のPDFから金額を抜き出す係」を作りたいなら、こんなイメージです。

▼ここから

name: invoice-reader description: 請求書PDFから金額・日付・取引先名を抽出する。請求書やPDFの数値抽出について聞かれたときに使う。 # 請求書リーダー ## 手順 1. PDFから表形式のデータを抽出する 2. 金額・日付・取引先名を整理する 3. 表にまとめて出力する

▲ここまで

この2項目さえ書けば、SKILLとして動き出す最低ラインはクリアです。

descriptionだけ、もう少し具体的に比べてみましょう。

△ 惜しい例：「請求書を処理する」 　→ 何をするかは伝わりますが、「いつ使うべきか」の手がかりが足りず、AIが呼び出すべき場面を見逃しやすくなります。

○ 良い例：「請求書PDFから金額・日付・取引先名を抽出する。請求書やPDFの数値抽出について聞かれたときに使う」 　→ 「何をするか」と「いつ使うか」の両方が入っているので、AIが自分の出番を正しく判断できます。

descriptionを書くときは、常にこの2点セットを意識するだけで、精度がぐっと上がります。

## AIはどうやってSKILLを見つけて、使うのか　3段階のしくみ

ここが地味に面白いところです。SKILLは、いきなり全部が読み込まれるわけではありません。3段階に分けて、必要な分だけ少しずつ読み込まれます。

□ 第1段階：名前と説明だけ（常に読み込み・1つあたり約100トークン） 起動時、AIはすべてのSKILLの「名前」と「説明」だけを、常にチェックしています。ここが軽量だからこそ、たくさんのSKILLを用意しておいても負担になりません。

□ 第2段階：手順の本文（呼び出されたときだけ・5000トークン未満が目安） 「これ、使えそうだ」とAIが判断したときだけ、SKILL.mdの中身（手順部分）を実際に読みにいきます。

□ 第3段階：追加ファイルやスクリプト（必要になったときだけ・使わなければ0トークン） SKILLの中にさらに詳しい参考資料や、実行用のスクリプトを同梱しておくこともできます。これらは、本当に必要になるまで一切読み込まれません。

つまりSKILL.mdは「棚にしまってある取扱説明書」。存在しているだけでは場所を取らず、開いたページだけをその場で読む——そんなイメージです。

## SKILL.mdは「フォルダ」の中の1ファイルにすぎない

もう1つ、押さえておくと安心なポイントがあります。SKILLは基本的に、1つのフォルダの中にSKILL.mdを入れる形で作ります。

invoice-reader/ ├── SKILL.md ← 必須。ここに手順を書く ├── scripts/ ← 任意。実行用のスクリプトを置ける │ └── [extract.py](https://extract.py/) ├── references/ ← 任意。詳しい参考資料を置ける │ └── format-guide.md └── assets/ ← 任意。テンプレートなどを置ける

SKILL.md以外は、すべて「あれば便利」という任意の付属品です。最初は本当にSKILL.mdの1ファイルだけでも、立派にSKILLとして機能します。慣れてきたら、スクリプトや参考資料を少しずつ足していけばOKです。

## どこで使えるの？（claude.ai／Claude Code／API）

SKILLは主に3つの場所で使えます。それぞれ少しだけ勝手が違います。

■ [claude.ai](https://claude.ai/) 設定の「Features」から、SKILLをzipファイルでアップロードします。Pro・Max・Team・Enterpriseのプランで、コード実行機能を有効にしていることが条件です。なお、アップロードしたSKILLは自分専用で、チームの他のメンバーと自動的に共有されるわけではありません。

■ Claude Code フォルダを置くだけで完了します。自分専用なら「~/.claude/skills/」、特定のプロジェクト用なら「.claude/skills/」の中にSKILL.mdを含むフォルダを置けば、Claudeが自動的に見つけて使ってくれます。

■ Claude API プログラムの中からskill\_idを指定して呼び出します。コード実行ツールと組み合わせて使う仕組みで、開発者向けの使い方になります。

注意しておきたいのは、これら3つの場所は自動的には繋がっていないという点です。claude.aiにアップロードしたSKILLがClaude Codeでそのまま使えたりはしません。使いたい場所ごとに、それぞれ用意する必要があります。

## 最初につまずきやすい、3つのポイント

実際に作り始めると、多くの人が同じところでつまずきます。先に知っておけば防げるものばかりです。

① descriptionを「何をするか」だけで終わらせてしまう descriptionには「何をするか」と「いつ使うべきか」の両方が必要です。「請求書からデータを抽出する」だけでは不十分で、「請求書やPDFの数値抽出について聞かれたときに使う」まで書いて、初めてAIが正しく選んでくれます。

② nameに紛らわしい文字を使ってしまう 大文字やアンダースコア、スペースはエラーの原因になります。小文字とハイフンだけ、と覚えておけば安心です。

③ 知らない人が作ったSKILLをそのまま使ってしまう SKILLはAIに新しい行動をさせる仕組みでもあるため、信頼できない配布元のSKILLを不用意に使うと、意図しない操作をさせてしまうリスクがあります。まずは「自分で作ったもの」「公式のもの」から始めるのが安全です。

④ SKILL.md本文に、なんでも詰め込みすぎてしまう 本文（第2段階で読まれる部分）はコンパクトに保つのが基本で、目安は500行程度までとされています。細かすぎる参考資料はreferences/フォルダの別ファイルに切り出しておけば、必要なときだけ読み込まれるので無駄がありません。「本文は要点だけ、詳細は別ファイルへ」を意識すると、後から見返しても迷いにくくなります。

## 3行でまとめると

・SKILL.mdは、コードではなくMarkdownで書く「AI用の手順書」

・必須項目はname（64文字以内）とdescription（1024文字以内、何をするか＋いつ使うかの両方）の2つだけ

・普段は棚にしまってあり、必要な場面でだけAIが開いて読みにいく仕組み

## 今日からできる、最初の一歩

理屈はここまでにして、実際に手を動かしてみましょう。難しく考えず、こんな順番で大丈夫です。

1. 自分が「毎回同じ手順でやっている単純作業」を1つ思い浮かべる（議事録の要約、定型メールの下書き、データの整形など、なんでもOK）
2. その作業名でフォルダを作る（例：meeting-notes/）
3. 中にSKILL.mdを作り、nameとdescriptionを書く（例：name: meeting-notes / description: 会議の議事録を要約する。議事録や会議メモの整理を頼まれたときに使う）
4. 普段自分がその作業をどんな手順でやっているか、箇条書きで書き出す（例：①決定事項を抜き出す→②担当者ごとに整理する→③次回までのタスクを最後にまとめる）
5. Claude Codeを使っているなら、そのフォルダを「.claude/skills/」の中に置くだけで完了

保存や公開の手続きは要りません。あなたのフォルダに、あなた専用の手順書が1つ増えるだけです。

Claude Codeを使っていない人は、[claude.ai](https://claude.ai/)の設定画面からSKILL.mdをzipファイルにしてアップロードする形でもOKです。手順の中身を考える部分は、どちらの方法でもまったく同じです。

慣れてきたら、2つ目、3つ目とSKILLを増やしていけば、AIはあなたの仕事の癖をどんどん覚えていきます。難しい設定もプログラミングも不要。まずは1個、今日中に作ってみませんか。
