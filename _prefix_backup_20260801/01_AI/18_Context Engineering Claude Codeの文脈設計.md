# Context Engineering Claude Codeの文脈設計

> [!info] 出典
> Hanako([@hanakoxbt](https://x.com/hanakoxbt)) 2026-07-27 投稿
> [元ポスト](https://x.com/hanakoxbt/status/2081800965502513286)

## 一行で言うと

プロンプト（入力45トークン）より前に読み込まれる約7,850トークンの「文脈」こそを設計対象にせよ。Contextは保存領域ではなく**毎リクエストかかる固定費**であり、削除優先・段階的開示・サブエージェント委譲で窓を健全に保つ規律が Context Engineering。

## 核心の比喩

> モデルが CPU なら、コンテキストウィンドウは RAM。

- 窓に書き込んだ1行は**そのプロジェクトの全リクエストで毎回再読み込み**される
- 「1行だから害はない」という默认を逆転させる — **有用と証明されるまで有罪**（guilty until proven useful）

## 窓の内訳（発話前の約7,850トークン）

Anthropic公表のセッションシミュレーションより。あなたが1文字打つ前に既に：

| 層 | 内容 |
|---|---|
| システムプロンプト | 最初にロード |
| Auto memory | 先頭200行 or 25KBのいずれか早い方でキャップ |
| 環境情報・MCPツール名・スキル1行説明 | 続く |
| グローバル CLAUDE.md / プロジェクト CLAUDE.md | 続く |
| **あなたの要求** | **約45トークン**（窓の0.5%未満） |

- プロンプトエンジニアリングは「45」を最適化する
- **コンテキストエンジニアリングは「7,850」を最適化する**

### 自分の実数を測る

- `/context` — カテゴリ別トークン内訳のグリッドを表示（システム/TLS/メモリ/空き/autocompactバッファ）。セッション開始時と途中の2回打つのが作法
- `/memory` — ロードされたファイルをその場で開く
- `/usage` — 直近の消費を skills / subagents / plugins / MCP サーバー別に分解

## コンテキストの4つの失敗モード（Drew Breunig 分類）

「多すぎる」は診断ではない。具体的な病名：

| モード | 何が起きるか | 症状 |
|---|---|---|
| **Poisoning（汚染）** | 幻覚が文脈に入り込み下流全部がそれを前提にする | 一貫して間違う。**騒々しい** |
| **Distraction（注意散漫）** | 蓄積文脈が訓練知識を圧倒。推論をやめて山に対するパターンマッチに堕ちる | 浅くなる |
| **Confusion（混同）** | 無関係なツール/ファイルが反応に影響する。窓にあったものに手を伸ばす | 関係ないものを使う |
| **Clash（衝突）** | 文脈の一部同士が矛盾する（「コメント書け」vs「絶対書くな」等） | 出力は正常に見えるが**毎回不可視の税**を払う。**静かで永続的** — これが高コスト |

Clash が厄介なのは、出力が一見問題ないため、半年前に書いたファイルの奥でずっと税を払い続ける点。

## 削除優先、計測次

見出し数字：Anthropic は Claude 5 世代で Claude Code のシステムプロンプトを **80%超削除**し、コーディング評価は**測定可能な低下ゼロ**だった。書き直しではなく削除。

手順：

1. **最小の評価ハーネス**を作る（気になるプロンプト10個＋良さの基準）。ないと推測になる
2. **ブロック単位で切る**（1行ずつはノイズフロアに埋もれて分からない）
3. ハーネスを走らせ、動かなければ削除を維持
4. **実際に壊れたものだけ復元**（驚くほど復元は稀）

## 禁止から原則へ（判断の移譲）

旧プロンプトの絶対規則（「コメント禁止」「docstring禁止」「計画書は作るな」等）は、最悪ケース回避としては正当だったが、一部プロンプトには間違っていた。新モデルは判断できるので規則は**コストに見合わなくなった**。

置き換え：**「その出力をせよ」ではなく「何を見るべきか」**

- `Always X` → `Xは通常ここでは正しい。理由は〜`
- `Never Y` → `Zを好め。Yはこのリポジトリの既知の落とし穴`
- ハードルールとして残すのは、Claude が**推論不可能なものだけ**：破壊的操作・セキュリティ境界・コンプラアンス・コードから見えない落とし穴

指針：`Write code that reads like the code around it — matching comment density, naming, idiom.`（周囲のコード那样に読めるコードを書け）

## 巻物ではなく木（Progressive Disclosure）

「CLAUDE.md に全実践を詰め込まねば Claude が見つけられない」は神話。**層ごとのコスト**を知る：

| 層 | ロードタイミング | コスト |
|---|---|---|
| スキル説明（1行） | 起動時常時 | 安い |
| スキル本体 | **使用時のみ** | 使うまで無料 |
| `.claude/rules/`（paths指定） | マッチファイル読込時 | それまで無料 |
| `disable-model-invocation` スキル | **名前で呼ぶまで完全に窓外** | 説明すら入らない。副作用あり（commit/deploy/送信）に最適 |

Anthropic 自身の指針：**プロジェクト CLAUDE.md は200行未満**。参照内容はスキルか paths ルールへ。

### CLAUDE.md に残す価値のあるもの

- リポジトリの目的の1行
- 誰も書いてないが全員が従っている慣習
- バグに見えるがバグでないもの
- Claude が理由なく違反する決定（例：共有型は1つのモノリスファイルに置く）
- より深いガイドへの**ポインタ**（ガイド本体ではない）

### 残す価値のないもの（ディレクトリ一覧で分かるもの）

フレームワーク・テストランナー・フォルダ構成・言語バージョン。Claude はファイルシステムを読む。「リポジトリを説明する」ことが1,000行 CLAUDE.md の最速の道。

### 知られざる mechanic

セッション compact 後、呼ばれたスキル本体は**再注入されるが1スキル5,000トークン・合計25,000トークンでキャップ、最も古いものから切り捨て**。切り詰めは**ファイル先頭を保持**。→ **重要な指示は SKILL.md の先頭付近に**。400行目に埋めた重要ルールは長いセッションで黙って消える。

## ツールの遅延読み込み

デフォルトで MCP ツールは**名前のみロード**（約120トークン）。フルスキーマは遅延され、Claude が tool search で必要時のみ取得。

- 大規模ツールセット＝窓の恒久混雑、というかつてのトレードオフが消えた
- **重複するツール説明が選択を混同する**（前出 Confusion）。取得（retrieval）を説明に適用すると**ツール選択精度が約3倍に向上**

## 読書を他所へ送る（サブエージェント）

ファイル読みが支配的：1ファイル 1,000〜2,500トークン。研究タスクが12ファイル触れると窓の1/3を黙って食う。

**サブエージェント委譲**：
- 独立した別窓・短いシステムプロンプト・CLAUDE.md のコピー・同じ MCP/skills、**しかし会話履歴なし**
- Anthropic の実例：サブエージェントが 6,100 トークン読んで 420 トークンの要約を返した。**6,100を払うべきところを420で済んだ**
- 依頼は「サブエージェントでこれを調べて、それから直して」だけでよい

**コストは正直に**：マルチエージェント構成はチャット比で**最大15倍**のトークンを消費しうる（各サブエージェントが core を再ロード）。総トークンと窓の清潔さを交換している。大抵は正しい取引だが、常に**意図的な**決定として。

## 意図的圧縮 vs パニック圧縮

長いセッションは窓が埋まる。自動 compact は**古いツール出力を先に消し、足りなければ会話を要約**するが、何が重要かを推測する。

意図的に圧縮：

- `/compact <指示>` — 「compact, focus on the auth bug fix」で残すものを指定
- `/clear` — 履歴を完全消去。**過小使用**。次タスクが直前20メッセージに依存しないなら古い会話は純ノイズ

### compact で生き残らないもの

- プロジェクトルート CLAUDE.md / auto memory → **ディスクから再注入**（生存）
- `paths` フロントマターのルール / ネストされた CLAUDE.md → **メッセージ履歴内**。要約で消え、マッチファイルを再読込するまで戻らない
- 絶対に持続させる必要があるルールは `paths` スコープを外すかルートへ移動

## 今週やる6つの文脈ジョブ

1. **窓を開いて読む** — `/context` をセッション開始時と1時間後に。メモリファイルが重ければ CLAUDE.md 過重を1コマンドで診断
2. **カットリストを生成させる** — `/doctor` でスキルと CLAUDE.md を走査し、過剰な絶対規則・矛盾・分割候補をフラグ
3. **ファイル間矛盾を探す** — CLAUDE.md と全スキルを一緒に読ませ、両立不能な指示対を列挙させる（静かな税の源）
4. **幹を木に分割** — 数行超はスキルか paths ルールへ、ポインタを残す。目標200行未満
5. **読書を委譲** — 数ファイル超の研究はサブエージェントへ。前後で `/context` を打ち、平らな線を見せる
6. **状態をファイルシステムへ** — Claude にプランファイルを書き換えさせ続ける。ディスクにあるので compact を生き残り、長タスクが途中で脈絡を失わない

## 所感・留意点

- **Prompt to Graph の5層**（[[10_Prompt to Graph Engineering 5層の統一モデル]]）の「Context層」を掘り下げた実践論。Prompt層（45トークン）とContext層（7,850トークン）の比率が鮮やか
- [[16_AIエージェントの正体はプロンプトだった]] と対：エージェントの自律性はプロンプト構造にあるとする一方、本ポストは「プロンプトより前にあるもの」の重量を主張。補完関係
- 数字の多くは Anthropic 公表・自己申告ベース。「80%削除で低下ゼロ」「15倍消費」「3倍精度」は外部検証されていない点に留意
- `/context` `/doctor` `/memory` `/usage` `/compact` `/clear` は Claude Code CLI のコマンド。Cowork 等の別環境では相当機能が無い場合がある
- 4層構造（Poisoning/Distraction/Confusion/Clash）と6ジョブは、このボルト自身の Lint 観点（矛盾・古い記述）にも適用できる
- Telegram 導線あり。手法本体は Anthropic 公式情報が土台なので原文（Anthropic docs / system prompt）に当たれば無料で足りる
