# Claude Code 超初心者ボルション道場

> [!info] 出典
> のいえん([@N01ennn](https://x.com/N01ennn)) 2026-07-30 投稿
> [元記事](https://x.com/N01ennn/status/2082554011199439194)
> 詳細メタデータ: [[21_Claude Code 超初心者ボルション道場（出典）]]

**Claude Code を今日から使い始める超初心者向けの実践ガイド**。「難しそう・何から始めればいいか分からない」という人に向けて、インストールから最初のボルト構築・CLAUDE.md の書き方・便利な使い方までを一気通貫で解説。Obsidian（ボルト＝vault）を Claude Code で操作する前提で書かれている。

## 想定読者

- Claude Code に興味はあるが**二の足を踏んでいる人**
- 「プログラミング不要って本当？」と半信半疑な人
- インストール〜最初の一歩で**つまずきたくない人**

## ゴール

**「自分のObsidianボルト（メモ群）を、Claude Code に整理・要約・拡張させる」** という具体的な成果物を、今日中に動かせる状態にすること。

## ステップ1：環境準備

| やること | ポイント |
|---|---|
| **Claude Code のインストール** | 公式手順に従い、APIキー／ログインを設定 |
| **ターミナルを開く** | VS Code 内ターミナルなどでOK。自分のボルト（フォルダ）を開く |
| **初回起動** | `claude` コマンドで起動。対話型プロンプトが立ち上がる |

> [!note] 「プログラミング不要」の意味
> コードを書く必要はないが、**Claude Code に対する指示（プロンプト）は書く**。それが「プログラミングの代わり」になる、という位置づけ。

## ステップ2：CLAUDE.md を置く

ボルトのルートに `CLAUDE.md` を置くと、**Claude Code が毎回自動で読む「運用ルール」**になる。

```markdown
# このボルトの運用ルール
- 資料は raw-sources/ に、要約は summaries/ に置く
- ファイル名には数字プレフィックス（01_ 等）を付ける
- 返答は日本語で
- Wikilink は [[ファイル名]] 形式で張る
```

こう書いておけば、**毎回同じ説明をしなくて済む**。Claude Code がルールを守って動く。

## ステップ3：最初のタスクを頼む

初心者がまず試すべき**安全で効果的な最初の一歩**：

1. **「このボルトの構成を整理して」** — フォルダ構成の提案・重複検出
2. **「この記事を要約して summaries/ に置いて」** — 資料→要約の自動生成
3. **「index.md を作って」** — 全ノートのカタログ自動生成

失敗してもファイルを壊すリスクが低く、Claude Code の便利さがすぐ実感できる。

## 使いこなすコツ

| コツ | 内容 |
|---|---|
| **小さく頼む** | いきなり巨大タスクでなく、1機能ずつ指示して確認 |
| **確認しながら進める** | 編集前に「こうしますがよいですか」と確認させる癖をつける |
| **plan モードを使う** | まず計画だけ立てさせ、レビューしてから実行（→ [[14_Claude Code 計画と実行を分けるワークフロー]]） |
| **CLAUDE.md を育てる** | うまくいったルール・失敗した手順を都度 CLAUDE.md に反映 |
| **Git／バックアップ** | 心配ならバージョン管理を併用。Claude Code 独自のバックアップも活用 |

## よくあるつまずきポイント

- **「何を頼めばいいか分からない」** → まず「ボルトを整理して」「要約して」など定型タスクから
- **「勝手に編集されて怖い」** → 確認ステップを挟む指示・planモードで抑止
- **「用語が難しい」** → CLAUDE.md に「初心者向けに説明して」と書いておけば配慮してくれる

## まとめ

- Claude Code は**「指示を書く」だけでボルト運用を自動化**できる
- 最初の一歩は **CLAUDE.md を置く** + **小さな定型タスクを頼む**こと
- planモード・確認ステップで安全に運用し、CLAUDE.md を育てていくのが成長のコツ
- 「難しそう」の正体は**最初の環境準備**。一度動けばあとは伸び代しかない
