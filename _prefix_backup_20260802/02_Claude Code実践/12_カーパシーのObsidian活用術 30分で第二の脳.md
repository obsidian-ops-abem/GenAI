## 一行で

Andrej Karpathy が2026年4月に公開した LLM Wiki 設計図を、**Obsidian + Web Clipper + Claude Code + タスクスケジューラ** で30分で実装する完全チュートリアル。読まない・分類しない・タグもつけない、ただ右クリックで `raw` フォルダに突っ込む。翌朝、Claude Code が3行要約＋記事ネタ案にして `wiki` フォルダに並べる。**人間の意志（やる気・記憶・判断）を設計から完全に外す**ことで初めて続く仕組みを作る。

## 核心: 人間の意志を設計から外す

- **読む意志・分類する意志・振り返る意志を全部あてにしない**
- 明日の自分が何も覚えていない前提で組む
- 続かない仕組みは、たいてい自分のやる気を部品として使っている。やる気は毎日は出ない
- → やる気が要る場所を一個ずつ機械に渡していく

> Karpathy: 知識をためる作業でしんどいのは、読むことでも考えることでもない。**事務仕事**のほうだ。タグを直す・リンクを張り直す・名前を統一する。この事務作業が得られる価値より速く増えるから、人はメモを捨てる。

## 4つの登場人物

| 役割 | ツール | 役割 |
|---|---|---|
| **集める係** | Obsidian Web Clipper | 右クリックで raw へ放り込む |
| **置き場** | Obsidian | フォルダを表示するだけ（頭脳は別） |
| **頭脳** | Claude Code | raw を読んで wiki に要約（Codex でも可） |
| **目覚まし** | Windows タスクスケジューラ | 毎朝頭脳を起こす（Claude が設定） |

## raw / wiki の一方通行ルール

```
人間 → raw フォルダ（右クリックで保存。読むだけ・書き換えない）
           ↓ Claude Code が毎朝読む
       wiki フォルダ（AI が要約を書く。人間は読むだけ・書き込まない）
```

- **AI は raw を書き換えない。読むだけ**
- **人間は wiki に書き込まない。読むだけ**
- 一方通行なので、AI が元データを消す事故も人間がまとめを壊す事故も起きない

> [!warning] フォルダを増やすと止まる
> 「記事用/ツイート用/論文用」など分けると、3週目に「これはどこに入れる?」で迷い保存が止まる。**分類は判断。判断は毎日は続かない。だから判断を仕組みから消す。** 入口は1つ、迷ったら全部 raw。※本ボルトは `01_raw-sources/` → `02_wiki/` の2層＋分類は AI（Ingest時）が担う構造で同じ思想。

## 30分構築の4ステップ

1. **右クリックで放り込む（5分）**: Obsidian + Web Clipper。ノート名を `{{date}}_{{title}}`、保存先を `raw` に。※保存ボタンは1回だけ
2. **フォルダを2つ作る（1分）**: `raw` と `wiki`（半角小文字）。一方通行ルール
3. **Claude にフォルダを見せる（5分）**: 保管庫で Claude Code を開き「raw の最新ファイルを3行で要約して」を1回手動で試す
4. **毎朝7時に自動実行（15分・本体）**: ネイティブ版 Claude Code インストール後、一言頼むだけ

## 自動実行の核心プロンプト

> Obsidian に保存した記事を、毎朝7時にまとめてほしい。そのまとめから、記事のネタも一緒に出しておいてほしい。パソコンが7時に起動していなかった日は、次に電源を入れたときに実行するようにして。自動実行では、公式ネイティブ版の `C:\Users\ユーザー名\.local\bin\claude.exe` を最優先で直接指定して。Microsoft Store アプリ内部の claude.exe は使わないで

4文の役割: (1) 要約 (2) ネタ出し（無いと要約で止まる） (3) 電源オフ日の保険（無いと黙ってスキップ） (4) Claude の場所指定（無いと朝だけ動かない）。

## 重要な教訓

- **「できました」を信用しない**: AI が設定したと言っても実際に入っていないことがある。タスクスケジューラの点検までさせる
- **必ず1回テストする**: この仕組みは失敗しても何も言ってこない（エラー画面も通知も出ない）。1回動くのを見ておけば「動いていると思ったら一度も動いていなかった」事故を防げる
- **週1回の死活確認**: wiki フォルダを開き新ファイルがあるか10秒で確認。増えていなければどこかで止まっている

## なぜ AI の使い道は「記憶を預けること」だったか

> Karpathy（公開2日前の X）: 最近の AI の使用量の大半が、プログラムを書くことよりも、**知識を扱うこと**に向かっている。

AI の使い道の本命は、賢い答えをもらうことでなく**自分の記憶を預けること**だった。AI を作った本人がそう言い出した。

## Claude でなくても構わない

Karpathy の設計図の冒頭: 「これはアイデアを書いた文書であり、自分の AI エージェントにコピペして使うために作った」。使える相手として **OpenAI Codex と Claude Code** が名前で挙がり、最初に挙がっているのは Codex。**パソコンのフォルダを読み書きできる AI ならどれでも成立**。特定の AI に縛られない。
