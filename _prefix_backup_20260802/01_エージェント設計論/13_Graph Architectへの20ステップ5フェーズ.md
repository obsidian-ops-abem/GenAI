# Graph Architect への20ステップ・5フェーズ

> **「Being a graph architect is not about the graphs. It's about clear thinking under complexity.（グラフアーキテクトであることはグラフについてでなく、複雑性の下での明確な思考についてである）」** — Loop を先に習得し、5つのパターンを学び、信頼性を築き、最後に「グラフにしない」判断を養う、ゼロからの20ステップ学習ロードマップ。

出典: [[44_Graph Architectへの20ステップ5フェーズ（出典）]]（Khairallah @eng_khairallah1, 2026-07-31。本文はユーザー提供クリップから再構成）

> [!note] 同著者の Loop 実戦解説の延長線
> 著者 @eng_khairallah1 は [[09_Loop Engineering Claude,GPT 実戦で効くもの]] の著者。本記事はその延長線上にあり、**Loop を Phase 1 で先に習得させる**構造。Loop と Graph を段階的に繋ぐ学習ロードマップとして位置付けられる。

## 一行で

グラフアーキテクト（乱雑な現実問題を見て、エージェント・ツール・チェック・人間の意思決定のネットワークを設計できる人）への**20ステップ・5フェーズ**の学習ロードマップ。**Loop 習得 → グラフモデル → 5パターン → 信頼性 → 「グラフにしない」判断**の順。各ステップに「do this」実演があり、全体で6-8週間。

## 核心: グラフは「複雑性の下での明確な思考」

- グラフアーキテクトとはフレームワークを暗記した人でなく、**混沌を見てそれを飼いならす最も単純な構造を見る人**
- それは時にグラフを意味し、**しばしば遥かに単純な何か（ループやスクリプト）を意味する**
- 根底の能力は「信頼できないモデルの周りに信頼できるシステムを設計すること」—— プロンプト/コンテキスト/ループ/グラフエンジニアリングと名前は変わるが価値は増すだけ

## 5フェーズ・20ステップ

### Phase 1: Master the Loop First（Step 1-4）—— 交渉不可

| # | ステップ | 要点 |
|---|---|---|
| **1** | ループが実際に何か | ループ=エージェント作業の原子（行動→結果→チェック→繰り返し）。グラフはこれら多数を繋いだだけ |
| **2** | 動くループを1つ構築 | 単純な実タスクで単一エージェントループを構築。手を動かすフラストレーションが最良の教師 |
| **3** | **verifier が全て** | チェックこそループの最重要。**弱い verifier のループは自信に満ちたゴミを速く生む**。これをマスタすればグラフが容易に |
| **4** | 単一ループがスケールで失敗する4通り | (a) クリーンに分岐できない (b) 並列実行できない (c) ステップ横断チェックポイントを強制できない (d) 失敗をただリトライ。**この4つがグラフの存在理由** |

> [!warning] Phase 1 をスキップするな
> 「グラフがトレンドだから単一ループから始めるのは後退に感じる」人がスキップし、グラフが壊れて理由が分からなくなる。**厳格な verifier を持つ単一ループを構築できるまで進むのを拒る**こと。全てがこの上に乗る。

### Phase 2: Learn the Graph Mental Model（Step 5-9）

| # | ステップ | 要点 |
|---|---|---|
| **5** | 3プリミティブ（nodes, edges, state） | ノード=作業単位、エッジ=次に何を走らせるかのルート、state=流れる共有情報。**どんなグラフもこの3つだけ** |
| **6** | **全ノードが LLM ではない** | **アーキテクトと初心者を分ける洞察**。最良のグラフは LLM ノードと**決定論的関数・ツール呼び出し・validator**を混ぜる。単純チェックは関数。**LLM 過剰使用が遅く・高価・不安定になる最も一般的な道** |
| **7** | 条件付きエッジ | 「エラーならここへ、さもなくばあそこへ」。直線ループが表現できない決定をグラフが表現する方法 |
| **8** | state の意識的設計 | 良いグラフ設計の半分は良い state 設計。少なすぎると機能せず、多すぎると推理不能 |
| **9** | 1つのフレームワークを選ぶ | **LangGraph が最も一般的な出発点**。概念はどこへでも転移。**フレームワーク飛びつきは忙しさを感じるだけで上達しない** |

### Phase 3: Master the Core Patterns（Step 10-14）—— 5パターンがほとんどをカバー

| # | パターン | 要点 |
|---|---|---|
| **10** | **The router** | 入力を見て正しいスペシャリスト/パスへルート。最も単純な分岐 |
| **11** | **The orchestrator-worker** | マネージャがジョブを分割・ワーカーへ割当・結果を組み立て。**ほとんどのマルチエージェントシステムの骨格** |
| **12** | **Parallel fan-out and fan-in** | 独立ノードが同時実行→単一ノードで収束。**ループが出せない真の速度をグラフが届ける方法** |
| **13** | **The evaluator-optimizer** | 一方が作業を生み、もう一方が基準で批評、通るまでループバック。**シリアスなグラフの品質エンジン** |
| **14** | **The human-in-the-loop gate** | システムが一時停止し人の承認を待つノード。**不可逆なもの（送信/公開/支払/削除）は全てこれを通す。本番ではオプションでない** |

### Phase 4: Build for Reliability（Step 15-18）—— 企業が実際に支払うもの

| # | ステップ | 要点 |
|---|---|---|
| **15** | validation gate | 名前付き・交渉不可のチェックポイント。**グラフのループに対する最大の優位性** |
| **16** | リカバリパス | ループは「リトライ」、アーキテクトは**意図的パス**（フォールバック/人間へのエスカレート/安全な失敗）。各失敗が何をするか前もって決める |
| **17** | チェックポイントと state 永続化 | 本物のグラフは一時停止・再開できる。**残したところから再開**（最初からでない） |
| **18** | 観測可能 | ロギングとトレーシングで各ノードが何したか・state がどう流れたか・どこが悪かったかを見る。**アーキテクトはデバッグ可能に構築したからデバッグできる** |

### Phase 5: Think Like an Architect（Step 19-20）—— 判断

| # | ステップ | 要点 |
|---|---|---|
| **19** | **グラフを構築"しない"ときを習得** | **この分野の最上位スキル**。ほとんどのタスクはグラフ不要。単一ジョブ+単一 verifier はループのまま。**作業が要求する前にグラフに手を伸ばすと、持たなかった分散システム問題を抱える**。アーキテクトは最も単純なものから始め、問題に複雑性を稼がせる。「これはグラフ不要」と言えることが熟達の証 |
| **20** | 本番・evals・チームのために設計 | evaluation suite（変更が助いたか損したかを測る）・文書化（チームメイトが理解）・拡張可能な設計。**巧妙なデモと企業が運用するシステムを分けるもの** |

## 人が止まる4つの場所

1. **Phase 1 をスキップ**（ループが basic すぎて）→ グラフが壊れて理由不明。厳格 verifier の単一ループまで進むのを拒るで突破
2. **フレームワークを集める**（構築でなく）→ 1つのフレームワークで3つの実グラフを構築するまで他に触らない。**1つの深さが多数の浅さに勝つ**
3. **パターン学習後すぐ過剰設計** → ループで済む問題に精密グラフ。**Step 19（グラフにしない）を本当の卒業とする。抑制がシニアスキル**
4. **「動く」で止まる** → Phase 4 をスキップし現実の予想外で壊れる。validation gate・リカバリ・デバッグ可能性を持つまで未完成と扱う

## 結論

> Being a graph architect is not about the graphs. It's about **clear thinking under complexity**.
>
> プロンプト/コンテキスト/ループ/グラフエンジニアリング —— 名前は変わるが、根底の能力（信頼できないモデルの周りに信頼できるシステムを設計する）は価値を増すだけ。**The term is two weeks old. The crowd is still arguing about what it means.** 8週間後、言葉についてのホットテイクを投稿し続ける側か、実際に構築できる少数の側か。
