# 本文（再構成）

## 病因：情報が散らかる人に共通する原因

メモを「溜めるだけ」の人は、どれだけ溜めても使えない。知識の「貯金箱」のつもりが**知識の「ゴミ箱」**になっている。もう1つの厄介な問題は**AIとの会話がリセットされる**こと。新しいチャットを開くたびに背景・好み・ルール・前回の結論をゼロから説明し直す無駄。

> 溜めたメモをAIが読める形で持っておけば、この無駄は一瞬でなくなる。これが「第二の脳」の発想。

## Obsidianが選ばれる3つの理由

1. **無料・ローカル保存・ただのテキストファイル** — 本体完全無料（商用OK）、日本語対応、ノートは Vault フォルダに入れるだけ、`[[リンク]]`で知識ネットワークができる、データは自分のPC内
2. **Claude Codeと相性抜群** — 「ただのフォルダ＋テキスト」が決定的。囲い込みがなく、将来別ツールへ移行してもファイルコピーだけで済む
3. （3つ目は本文では明示的に番号付けされていないが、上記2点が核心）

> ノートの正体は「ただのフォルダの中にあるテキストファイル」。これが Claude Code との相性を決定的にしている。

## 5分で完了——最速セットアップ（3ステップ）

```bash
cd ~/Documents/MyVault
claude
```

**ステップ3: キックオフプロンプトを打つ**

```text
ObsidianをAIとの情報管理に使いたい。
僕の目標・タスク・好みについて質問して、
すり合わせが終わったらVaultのフォルダ構造と
CLAUDE.mdを提案・作成して。
```

すると Claude Code が**逆に質問**してくる（「どんな情報を管理したい？」「仕事用？個人用？」）。答えていくだけで、AIが自動で：
- フォルダ構造を自動作成
- CLAUDE.md（AIへの指示書）を自動生成
- タグ規則・テンプレートも作成
- 安全ルールまで提案
- 既存ノートがあれば構造に合わせて自動整理

**コードを書く必要は一切ない。**

## CLAUDE.mdが「脳の設計図」になる——全てを決める

第二の脳の質は CLAUDE.md で決まる。セットアップより核心。

### CLAUDE.mdとは

Claude Code が起動時に自動で読む「指示書」。プロジェクトルートに置くただのテキストファイル。ここに書いたルールをAIが毎回読んで守る。「毎回AIに説明していたこと」を1回書けば終わり。

### CLAUDE.mdに書くべき5つの要素

1. **フォルダ構造の説明** — どこに何を置くか
2. **タグ規則** — 「kebab-case（ハイフンつなぎ）で統一」等
3. **ノートのテンプレート** — 冒頭に書く型
4. **リンク規則** — いつ `[[リンク]]` を張るか
5. **安全ルール** — 「元ノートは消さない」「削除は提案だけ」

### フォルダ構成の実例——2パターン

**パターン①: 知識ベース型**

```text
vault/
├── CLAUDE.md      （AIへの指示書）
├── books/         （読書メモ）
├── articles/      （記事クリップ）
└── wiki/          （分野別の知識ノート）
```

**パターン②: プロジェクト型**

```text
project/
├── CLAUDE.md      （案件概要・関係者・ルール）
└── docs/
    ├── daily/     （デイリーノート）
    └── research/  （調査メモ）
```

両方の併用も可。最初は①から始めるのがおすすめ。

### 制約を厳密にするほどAIの出力が上がる

「ゆるいルール」だとAIも迷う。具体的に決めておくと：
- 「タグはkebab-caseで統一」→ 表記ゆれゼロ
- 「読書メモは books/ に保存」→ 保存先で迷わない
- 「1ファイル=1トピック」→ 検索精度向上

> **制約は「縛り」じゃなく「設計図」。明確なほどAIの仕事が正確になる。**（AIエージェント100体以上で確信）

## 「あれどこだっけ」が一生なくなる——6つの運用パターン

### まずはこの3つから

**① 知識検索 — 「あれどこ？」を一発解決**（一番感動した機能）

```text
プロジェクトXでリスクに言及したメモだけ
抜き出して要約して
```

キーワード検索では見つからない**「意味」ベースの検索**が通る。

**② 散らかったメモの自動整理**

```text
Clippings内のノートを内容ごとに
適切なフォルダへ振り分けて
```

AIが中身を読んで自動仕分け。週末のメモ整理が消滅。

**③ 自動タグ付け**

```text
今週作成・更新したノートに
規則に沿ったタグを付けて
```

CLAUDE.md の規則に従い一貫したタグを付与。手動タグ付けの時代は終わり。

### 慣れたら使いたい応用3パターン

**④ ノート間リンクの自動生成**

```text
このノートに関連しそうな既存ノートを
探して[[リンク]]して
```

知識ネットワークが勝手に育つ。思いがけない繋がりを発見。

**⑤ 週次レビューの自動生成**

```text
今週更新されたノートを一覧して要約して。
停滞プロジェクトにフラグを立てて。
```

「何をやっていて、何が止まっているか」が自動可視化。

**⑥ 過去の自分との対話**

```text
1年前、転職について何を考えていた？
```

AIが過去ノートを検索して回答。「過去の自分と対話できる」体験。

## 2,000時間の運用で辿り着いた設計ルール7つ

本文で最も価値がある部分。**「回り続ける脳の設計」**。

### ルール①〜④: 散らかりを構造で防ぐ

特に効果を実感しているのは③。

```text
保存前に既存ノートと重複がないか確認して
```

これを CLAUDE.md に1行追加するだけで、AIが勝手に重複チェック。④も強力：判断基準を書いておくだけでAIが迷わなくなる。

### ルール⑤〜⑦: AIが迷わず動ける命名と棚卸し

**ルール⑤: 命名規則をプレフィックスで統一** — ファイル名の頭に「種別」を付ける:
- `feedback_` — 学び・修正指示
- `project_` — 進行中の案件
- `reference_` — 参照情報
- `user_` — 個人の設定・好み

ファイル名で種別がわかると**AIの検索が段違いに速くなる**。

**ルール⑥: ノート冒頭にメタ情報を付ける** — 各ノート先頭に「名前・説明・種別」を書く。AIが「開く前に関連性を判断」でき、全ノートを読む必要がなくなる。

**ルール⑦: 月次で棚卸し** — 「溜める」だけじゃダメ。「捨てる」まで仕組み化する:

```text
完了済み・古い情報を整理して。
削除候補は一覧にして提案だけして。
```

> **「捨てる」まで仕組み化できたら、情報管理の上位1%に入れる。**

## やらかす前に知っておきたい——安全に使う3つの注意点

AIはファイルの移動・削除・書き換えができる。**誤操作での消失リスクはゼロではない。**

### バックアップは絶対

- **VaultをGit管理** — 「変更前に今の状態を保存して」と指示するだけ
- **クラウドに置く** — iCloud/Dropbox でバージョン履歴から復元可能
- **初回は丸ごとコピー** — 大規模整理の前にフォルダごとコピー

### CLAUDE.mdに書く安全ルール

```markdown
## 安全ルール
- 元のノートは絶対に削除しない
- 整理は「移動」のみ。削除は「提案」だけにする
- 大規模な変更の前にGitで現在の状態を保存する
```

この3行で：AIが勝手に消さない／削除前に確認／元に戻せる。**AIの暴走リスクが激減。**

### 「小さく試してから一括」が鉄則

- まず2〜3ファイルでテスト実行
- AIの整理結果が意図通りか確認
- 問題なければ範囲を広げる
- いきなり全ノートに走らせない

> 20万円以上の案件を1時間で完遂する僕らでも、「小さく試す」は絶対に省略しない。

## さらに攻めたい人へ——MCP連携とClaudianプラグイン

シンプル版で第二の脳としては十分。メイン運用もシンプル版。上級オプション2つ:

- **MCP連携** — Claude Code が Obsidian のタグ・バックリンクを直接操作可能（プラグイン2つ＋コマンド入力）。**体感ではシンプル版で8割カバー**。物足りなくなってからで十分
- **Claudianプラグイン** — Obsidian 内に Claude Code を統合。ターミナルを開かない選択肢。Claude有料プラン（月20ドル以上）＋BRAT経由インストール

> 僕らの結論は「シンプル版で十分」。まずはターミナルで `claude` と打つところから。
