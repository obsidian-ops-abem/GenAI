# 原文（npaka 記事・構造化）

## 1. はじめに
2026年9月15日、TypeSafe AI が「Jev」を発表。ChatGPT のように文章を生成するのではなく、**入力された状況から、型付きの判断とその確率を高速に返す**ことに特化。応答時間は公表値で **70〜500ms**。DOOM を約10回/秒で操作するリアルタイムデモも公開。

## 2. Jevとは
### 2-1. 文章ではなく「判断」を出力する
- LLM: 入力 → トークンを1つずつ生成 → 文章/JSON/コード
- Jev: **State（状況）+ Questions（判断してほしいこと）→ 型付きの判断 + 確率**
- 例「商品が壊れていたので返金してほしい」→ `refund: noul 0.97` / `department: choice billing (confidence 0.71)` / `human_review: noul 0.31`
- TypeSafe の表現: **「非構造化された状態を入力し、型付きの確率的な判断を出力する」**（unstructured state in, typed probabilistic decisions out）

### 2-2. System One Model
Kahneman『Thinking, Fast and Slow』の System 1（高速直感）/ System 2（熟考）に由来。Jev は長い推論や文章生成でなく、**状態 → 高速に判断 → プログラムが実行** の短いループに重点。

## 3. なぜ高速なのか
### 3-1. 応答時間は70〜500ms
### 3-2. 複数の判断を並列に出力する
LLM は文字列をトークン単位で順番に生成。Jev は TypeSafe が **「parallel sampler」** と呼ぶ仕組みで**複数の判断を並列出力**（敵がいる？→0.96 / 攻撃する？→0.84 / 左？→0.13 / 右？→0.81）。この設計＋**新しいモデルアーキテクチャと RLCD と呼ばれる学習手法**が高速性の源泉。

## 4. DOOMをリアルタイム操作
- **1秒間に約10回（10Hz）**の問い合わせ。平均約100msに1回、ゲーム状態→Jev→判断→操作のループ
- コストは**約7ドル/時**（毎秒10クエリ）
- ※Jev は画面を直接見ていない。ゲーム状態を**構造化されたデータとテキスト**として渡している

### 4-2. リアルタイムAIへの応用
- ロボット例: 掴む？0.91 / 危険？0.03 / 対象A？0.88
- 100ms 前後ではモーター直接のサーボ制御には向かないが、**対象物選択・行動切替・異常検出・タスク判断など数Hz〜10Hzの上位レベル判断**には利用可能
- 70ms は米国西海岸等での測定値。**日本からクラウド API ではネットワーク遅延が加わる**

## 5. LLMとは何が違う？
### 5-1. 判断の出力に特化する
LLM の Structured Outputs との違いは「JSON を壊さない」ことでない。LLM は**生成してから制約**、Jev は**最初からソフトウェアが利用する型付きの判断と確率を出力**に特化した設計。

### 5-2. 「ハルシネーションしない」の意味
- TypeSafe は「can't hallucinate」と説明 — 自由な文字列を生成せず定義済みの型・選択肢以外を出力しない、の意
- **「判断を間違えない」意味ではない**。型や形式が正しくても誤った選択肢を選びうる
- **「型が正しい」ことと「判断が正しい」ことは別**

## 6. LLMと組み合わせる
- ユーザー → Agent →（Jev: 高速な分類・判断 / LLM: 推論・文章・コード生成）
- 「このメールは重要か」「次のツールを実行すべきか」「結果に問題がないか」は Jev へ。複雑な推論・生成だけ LLM
- TypeSafe の表現: **「スマートなif文」（smart if-statements）** — AI版 if 文としてアプリの各所に配置

## 7. まとめ
- 現在は Early Access で性能値の多くは TypeSafe による評価
- **「高性能なAIを1回呼ぶ」のではなく「小さなAI判断を大量かつ高速に呼ぶ」** — AIエージェント・ゲーム・ロボットにおけるリアルタイムAIの新しいアプローチ
