# 講演内容（主題別再構成・日本語）

## Claude Code とは
- 新世代の AI コーディングアシスタント。**行補完でなく完全にエージェント的**（機能構築・関数/ファイル全体・バグ修正全体）
- **全ツール・全 IDE・全ターミナルで動く**（ワークフローを変えなくてよい）。ローカル/SSH/チームどこでも

## 初期セットアップ
- `/terminal-setup`（shift+enter 改行）・`/theme`・`/install-github-app`（**GitHub issue/PR で Claude をメンション**）・許可ツールのカスタマイズ（毎回承認を減らす）
- **macOS のディクテーションでプロンプトを話す**（具体的なプロンプトが楽になる）

## Tip 1: コードベース Q&A から始める
- **Anthropic の新入社員技術オンボーディングで実際に教えている最初のステップ**
- 「このコードはどう使われる?」「このクラスの実例は?」→ テキスト検索でなく一段深く使用例を探す
- **git 履歴の質問**: 「なぜこの関数は15引数で変な名前?」→ 履歴を辿り導入経緯・ issue を要約。**システムプロンプトに履歴指示なし（モデルが優秀だから自力で知っている）**
- GitHub issues を fetch で参照。**毎週月曜のスタンドアップ用に「今週出荷したもの」を生成しコピペ**
- オンボーディングのコツ: 派手なツールや編集から始めず**質問から**。何がワンショット可能/REPL 要かの感覚を育てる

## Tip 2: 計画→承認→実装
- いきなり「この3000行機能を実装」ではなく「**ブレインストーム・計画を作って承認を得てから書く**」。plan モード不要でプロンプトで可能
- **反復のためのツールを与える**: ユニットテスト/Puppeteer スクショ/iOS シミュレータ スクショ。**「結果を見る方法」を与えれば3回反復でほぼ完璧になる**（初回はそこそこでも）
- 自分のチームのツールを教える（ドキュメントや CLI を読ませる・CLAUDE.md に保存）

## Tip 3: コンテキスト（CLAUDE.md 階層）
- **プロジェクトルートの CLAUDE.md** は毎セッション自動読込・**ソース管理にチェックインしてチーム共有**
- **CLAUDE.local.md**（非共有・個人用）・**ネストした子ディレクトリの CLAUDE.md**（そのディレクトリで作業時にオンデマンド読込）・**enterprise root**（全社共有）
- 中身: 一般 bash コマンド・MCP ツール・アーキテクチャ決定・重要ファイル。**短く保つ**（長いとコンテキストを消費するだけ）
- **権限も階層で**: エンタープライズポリシーで bash コマンドを自動承認・**特定 URL を永久ブロック（従業員が上書き不可）**
- **MCP サーバーを .mcp.json でチェックイン**→チーム全員にインストールを促す（例: Puppeteer MCP で E2E テスト・スクショ反復）
- `/memory` で読み込まれる全メモリを確認・`#` で記憶する際どのメモリか選択
- 迷ったら**共有プロジェクトコンテキストから**（一度書いて全員が恩恵=ネットワーク効果）

## キーバインド
- **shift+tab**: 自動承認編集モード（bash は承認のまま・正しい軌道の時やテスト反復時に）
- **#**: 記憶・**esc**: 実行中断し軌道修正（20行中19行正しい時）・**esc×2**: 履歴を遡る・`--resume`/`--continue`・**Ctrl+R**: 出力全文表示（モデルが見ているのと同じ）

## SDK（`claude -p`）
- **Claude Code が使っているのと同じ SDK**。プロンプト・許可ツール・出力形式（JSON/ストリーミングJSON）を指定
- **Unix ユーティリティとして**パイプ: `git status | claude -p "..." | jq`・GCP バケットの巨大ログを流入・Sentry CLI からのデータを処理
- CI・インスタンスレスポンス・パイプラインで常用

## 並列（パワーユーザー）
- **複数の SSH セッション/tmux・同一リポジトリの複数チェックアウト・git worktree で隔離しながら複数 Claude を並列**

## Q&A 抜粋
- **最難関は bash の安全性**: bash は本質的に危険でシステム状態を予期せず変える。**毎回手承認では生産性が死ぬ**。静的解析で安全にスケールさせる設計が難しい
- **CLI を選んだ理由**: ①Anthropic 内部は IDE が多様（VS Code/Zed/Xcode/Vim/Emacs）→**ターミナルが最大公約数** ②**モデルの向上が速く年末には IDE を使わなくなっている可能性**→UI 過剰投資を避ける
- **マルチモーダル**: 画像をドラッグ&ドロップ/パス/ペースト。モックを渡して実装させ Puppeteer で反復
- Anthropic 技術職の約80%が毎日使用（研究者はノートブックツールも）
