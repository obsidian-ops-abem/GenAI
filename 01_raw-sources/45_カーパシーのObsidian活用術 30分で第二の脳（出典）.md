## 1章 完成形: 翌朝どうなってるか

夜20:54に保存した21,369字の記事が、翌朝1,751字（約12分の1）になっている。見出しは2つ:

- **3行要約**（元記事の要点を3つ）
- **発信に使える気づき**（note に使える視点・体験と結びつく論点・書けそうなタイトル案3つ）

要約で終わらず**書く直前まで進んだ状態**で朝を迎えられる。読んだのは要約の10行だけ。その日の分（10本保存すれば10要約）は、毎朝1枚の**表紙**（「本日の新規クリップ：3件」＋リンク）にまとまる。朝に開くのはこの1枚、タイトルと3行を流し読みして引っかかったものだけ開く。所要2分。

## 2章 記事のネタまで出てくる

溜まった要約を掛け合わせた**記事案**が、すでに要約の下に置いてある。AI に「AI について記事を書いて」と頼むと一般論しか出ない（材料を渡していないから）。本仕組みは逆: **あなたが保存してきた記事だけを読ませる**。何を保存するかを選んだのはあなた。その選び方は他の誰とも一致しない。だから出てくるものも一致しない。

> AI に何を聞くかで差がつく時代は終わりかけている。これからは、**AI に何を食べさせたか**で差がつく。

溜まるほど強くなる: 1週間目は5本から3ネタ程度だが、3ヶ月目には「先月のあの話と昨日の話は逆のことを言ってる」と**人間が忘れている過去の材料を機械は忘れない**から指摘が出る。ネタ切れが消える。

## 5章 手順1: 右クリックで放り込めるようにする（5分）

### Obsidian を入れる（3分）
公式サイトからダウンロード（無料・個人利用は登録不要）。起動して「保管庫（Vault）を作成」。既存 Obsidian ユーザーは現在の保管庫のままでOK。

### Web Clipper を入れる（3分）
Chrome/Edge は Chrome ウェブストアで「Obsidian Web Clipper」検索（提供元 obsidian.md の公式・ユーザー90万・評価4.8）。Firefox は Firefox Add-ons。**ピン留め**までやる（Firefox はピン留めしないとアイコンが見えない）。

### 最初の1本を保存しながら設定
適当な記事で右クリック→メニュー一番下の「Obsidian Web Clipper」。保存画面で:
- **保管庫の欄**: 作った保管庫を選ぶ（1文字でも違うと無言で失敗する落とし穴）
- **フォルダの欄**: `raw` と入力

### ファイル名に日時を付ける（1分）
歯車マーク→設定→テンプレート→デフォルト。「ノート名」を `{{date}}_{{title}}` に書き換え。「ノートの場所」を `Clippings` から `raw` に変える。

### 注意
- 保存ボタンは1回だけ（2回押すと同じ記事が2本できる）
- `Ctrl+Shift+O` で保存画面、`Alt+Shift+H` でハイライト
- ログイン必須ページは本文が空になることがある（目的は AI に読ませる材料なので本文テキストさえ入れば足りる）

## 6章 手順2: フォルダは2つだけ作る（1分）

`raw`（人間が保存したいデータを入れる場所）と `wiki`（AI が raw からのデータを書く場所）を半角小文字で作る。

### ルールは一方通行
- **AI は raw を書き換えない。読むだけ**
- **人間は wiki に書き込まない。読むだけ**

流れが一方通行なので、AI が元データを消す事故も、人間が AI のまとめを壊す事故も起きない。

### フォルダを増やすと止まる
海外の人気記事は「記事用/ツイート用/論文用」など5種類に分ける構成を勧めていた。綺麗だが3週目に「ツイートで紹介された論文の解説記事。どこに入れる?」で迷い、保存が止まる。**分類は判断。判断は毎日は続かない。だから判断そのものを仕組みから消す。** 入口は1つ、迷ったら全部 raw。

## 7章 手順3: Claude にフォルダを見せる（5分）

### 登場人物は4人
- **集める係**: Web Clipper（右クリックで raw へ）
- **置き場**: Obsidian（フォルダを表示するだけ）
- **頭脳**: Claude Code（raw を読んで wiki に要約）
- **目覚まし**: Windows タスクスケジューラ（毎朝頭脳を起こす・次章で Claude が設定）

### 1回だけ手で要約させてみる
Claude Code を保管庫のフォルダで開き、日本語で:

> Obsidian の保管庫にある raw フォルダの、一番新しいファイルを読んで、3行で要約して

数秒で要約が返れば成功。Claude はフォルダを読めている。頼み方を変えれば自由にカスタマイズできる（5行要約・初心者向け説明・反論・X 投稿文作成など）。

## 8章 手順4: 毎朝7時に勝手に走らせる（15分・本体）

### 下準備（3分）
ターミナル/PowerShell で公式インストーラを実行:
```
irm https://claude.ai/install.ps1 | iex
```
自動実行から呼べるネイティブ版 Claude Code を追加（現在のアプリはそのまま）。終わったら Claude Code に「ちゃんと使えるか確認して」と頼む。

### 「毎朝手でやればいい」が続かない理由
朝はメールも通知も予定もある。昨夜記事を保存したことを翌朝の自分は覚えていない。**覚えていなくていい状態にする**のが本章の目的。

### 言うのはこの一言だけ
> Obsidian に保存した記事を、毎朝7時にまとめてほしい。そのまとめから、記事のネタも一緒に出しておいてほしい。パソコンが7時に起動していなかった日は、次に電源を入れたときに実行するようにして。自動実行では、公式ネイティブ版の `C:\Users\ユーザー名\.local\bin\claude.exe` を最優先で直接指定して。Microsoft Store アプリ内部の claude.exe は使わないで

- 2文目: ネタ出し部分（無いと要約で止まる）
- 3文目: 電源オフの日の保険（無いと黙ってスキップされ続ける）
- 4文目: Claude の場所指定（無いと朝だけ動かない）

長い指示文は不要。足りないことは向こうから聞いてくる（保管庫の場所・ブラウザ・保存する記事の種類・何時）。

### 「できました」を信用しない
AI が「設定しました」と言っても実際に入っていないことがある。必ず点検させる:

> タスクスケジューラの登録を実際に開いて確認して。「スケジュールされた時刻にタスクを実行できなかった場合、すぐにタスクを実行する」と「タスクを実行するためにタスクを解除する」がオンになってるか見て、なってなければ直して。あと、失敗したときに15分おきに3回まで再試行する設定も入れて

ノートパソコンは「AC 電源で使用している場合のみタスクを開始する」をオフにさせる（充電ケーブルを挿していない朝は動かないため）。

### できあがったら必ず1回テストする
> テストしてくれ

この仕組みは失敗しても何も言ってこない（エラー画面も通知も出ない）。1回動くのを見ておけば「動いていると思ったら一度も動いていなかった」事故を防げる。動いている間は黒い画面が勝手に開くが正常。wiki フォルダに要約ができていれば成功。

## 9章 動かないときはこう言ってください（症状別）

トラブルシューティング10症状（アイコンが出てこない・引数エラー・手動は成功するが自動で動かない・実行記録あるのに何も増えない・関係ない返事・長い記事だけ失敗・ある日から止まった・全角で打ってしまった・朝起動したのにまだ・タスクスケジューラが開けない）。共通する注意は1つ: **この仕組みは失敗しても何も言ってこない**。対策は週1回 wiki フォルダを開いて新ファイルがあるか10秒で確認すること。

## 結論: 溜める場所から、勝手に育つ場所へ

> やっていることは、要するに「自分の意志を、設計から外した」だけ。

読む意志も、分類する意志も、振り返る意志も、全部あてにしない。**明日の自分が何も覚えていない前提で組む。そうしたら初めて続いた。**

続かない仕組みは、たいてい自分のやる気を部品として使っている。やる気は毎日は出ない。だから、やる気が要る場所を一個ずつ機械に渡していく。

> 集めるのは自分。読むのは Claude。
>
> 今日やることは、右クリック1回だけです。
