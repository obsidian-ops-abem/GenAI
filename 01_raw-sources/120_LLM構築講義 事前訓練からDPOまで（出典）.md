# 講義内容（主題別再構成・日本語）

## 何が重要か（5要素）
**アーキテクチャ／損失と訓練アルゴリズム／データ／評価／システム**。学術界はアーキテクチャと損失に集中しすぎ。**実務で本当に効くのはデータ・評価・システム**（産業界が集中する場所）。

## 1. 事前訓練（言語モデリング）
- LM=トークン系列の確率分布のモデル。**自己回帰分解**（連鎖律）で次トークン予測
- 訓練=次トークン分類→**交差エントロピー損失**（テキスト対数尤度最大化と同値）
- 欠点: 長い文の生成に時間がかかる（逐次）

## 2. トークナイザー
- 単語単位（タイポ・タイ語等スペースなし言語に弱い）と文字単位（系列が長くなりすぎ・attention は長さの2乗）の間
- **BPE**: 大規模コーパスで最頻ペアを反復マージ。平均トークン=3-4文字
- 適用時は**常に最大トークンを選ぶ**。小トークンは保持（タイポ表現用）
- **数学が苦手な理由**: 数字がトークン化され合成ができない。GPT-4 の大きな変更点のひとつは**コードのトークン化変更**
- 将来: 文字/バイト単位への回帰を望む声（長さスケールしないアーキテクチャができれば）

## 3. 評価
- **Perplexity** = 2^(平均損失)。「モデルが迷っているトークン数」。完全=1／無知=語彙サイズ。2017→2023 で70→10未満。**語彙サイズ依存で学術ベンチには不向き（開発では重要）**
- **MMLU** 等の集約ベンチ（Stanford HELM・HF Open LLM Leaderboard）
- 課題: 評価方法の非標準（同じモデルで成績が大きく変わる）／**テストセット混入検出**（順番通り生成しやすいかで判定するトリック）

## 4. データ（「全てのインターネット」とは）
- Common Crawl 約2,500億ページ・1PB → **HTML からテキスト抽出**（数学・フォームの重複ヘッダが難しい）→ 有害/PII フィルタ＋ブラックリスト → **重複排除**（スケールで困難）→ ヒューリスティック濾過（外れ値トークン分布・単語長・短すぎ）→ **モデルベース濾過（Wikipedia 参照ページ由来か分類する分類器を訓練）** → ドメイン分類と重み付け（**コードを増やすと推論が良くなる・本も増量・エンタメ減量**）→ 訓練終盤は**高品質データで学習率を下げ過剰適合**
- 規模: 学術150B→**15Tトークン**（Llama3=15T・GPT4 はリークで約13T）
- 「**データは未解決。合成データ・マルチモーダル・秘匿（競争・著作権）**」

## 5. スケーリング則
- より多くのデータ・より大きなモデル=より良い性能（**過学習は起きない**）。対数スケールで予測可能
- 新パイプライン: スケーリングレシピ→**小モデル群でハイパラ調整→則を当てはめ外挿→最終巨大モデルを27日訓練**（旧: 30モデル1日ずつ）
- **Chinchilla**: 最適=**パラメータ当たり20トークン**。推論コスト考慮では**150トークン/パラメータ**（小さいモデルを長く使う方が安い）
- アーキテクチャの小差は**切片を少し変えるだけ**（10時間長く訓練する方が勝る）。**良いデータはスケーリング則そのものを改善**（Sutton「計算を活かせるものだけが重要」）
- **Llama3-405B の勘定**: 15.6T×405B≈3.8e25 flops（**1e26 の規制審査線をわざと下回る**）・16k H100×70日=2,600万 GPU 時間・**計約7,500万ドル**（GPU 賃貸5,200万+人件費2,500万）・CO2 4,400トン（JFK-ロンドン往復2,000枚分・今はまだ問題でないが GPT-6/7 で×100なら問題に）

## 6. 事後訓練（アライメント）
- GPT-3 に「月着陸を6歳児に説明して」と聞くと「重力理論を説明して」という**次の質問を续ける**（インターネットの分布）。求めるのは応答
- **SFT**: 人間の望ましい応答で微調整。**ChatGPT の躍進の鍵**
- **Alpaca**: 人間175 QA→text-davinci-003 で52,000 QA 合成→LLaMA-7B を SFT
- **LIMA**: 2,000→32,000 に増やしてもあまり変わらず。**SFT は「フォーマットの学習」で、事前訓練分布の中の「どのユーザータイプに最適化するか」の選択**
- SFT の3問題:
  1. **人間の能力に制限**（良い本を書くより見分ける方が得意）
  2. **ハルシネーションの仮説**: 人間の答えに事前訓練で知らない事実が含まれると、モデルは「もっともらしい作り話」を学習する（Monopoly の参照例）
  3. **コスト**（完全な解答を書くのは高い）
- **RLHF**: 指示ごとに2応答生成→人間が選好→**選好を最大化**
  - 報酬: 二値（スパース）より**報酬モデル**（分類器・ソフトマックス logit で連続）
  - **PPO**（ChatGPT が使用）: 報酬モデル+正則化（過最適化防止）。**PPO 後のモデルは尤度が意味を失う**（分布モデルでなくなる→perplexity で評価できない）
  - **DPO**（Stanford）: RL を使わず**好きなものの尤度を最大化・嫌いなものを最小化**。数学的に PPO と同じ大域最適解（仮定の下）。**実装が桁違いに簡単で性能同等**→標準に
- **選好データの人間の問題**: 遅く高い／正確性より**長さ等の形式**を見る／标注者分布のシフト／クラウドソーシング倫理
- **LM as judge**: 人間3,000件300ドル→**LM は50倍安く人間モードとの一致率が人間自身（66%）より高い**（分散ゼロ）
- **AlpacaEval**: 勝率ベースの自動リーダーボード。Chatbot Arena と90%相関・10時間未満。**欠点: LM は長い出力を好む**（「verboseにして」だけで勝率50%→64.4%・「簡潔に」で20%）→**回帰分析で長さを制御**
- 質疑: SFT は全重みを変更（LoRa は一部）。**事前訓練=重みの初期化と見なせば特別なものではない**。人間+LM 協働（LM 生成+人間編集）が情報量的に有望

## 7. システム（最後8分）
- GPU: スループット最適化（CPU=レイテンシ）・**行列積が10倍速**・計算はメモリ/通信より速く進化→**最適化しないと GPU はアイドル**・**MFU（モデル flop 利用率）50% で上出来**
- **混合精度**: 計算は16bit・重みの保存と更新は32bit（学習率が小さくても差を表現）
- **オペレータ融合**: PyTorch の行ごとに DRAM⇔計算ユニットを行き来する無駄→**融合カーネルで1往復に**
