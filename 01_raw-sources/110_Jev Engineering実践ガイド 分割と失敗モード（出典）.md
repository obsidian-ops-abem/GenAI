# 原文（構造化再構成）

## What Jev Actually Is

Jev は **System One モデル**（Kahneman の System 1/System 2 から）。TypeSafe の賭け: **ソフトウェア内部の決定の大半は System 1 判断**であり、私たちはそれを System 2 をレンタルして行ってきた。

- state（文脈）+ 型付き質問を送ると、**全質問を単一の並行パスで評価**し、較正済み確率付きの型付き回答を返す。トークン毎の生成なし・パースする文字列なし・チャットなし
- 公表値: 70-500ms・$0.042/百万入力トークン・**出力トークン無料**
- 最もシンプルなメンタルモデル: **「Jev は賢い if 文」**。コードは計算できる条件では分岐するが（`order.total > 100`）、「この顧客は怒っているか？」「このメールは請求関連か？」という**判断条件**で壊れる。Jev はその分岐

## Step 1: Make the Split（3バケット分類）

1. **テキストを作る → LLM**（ブリーフィング執筆・メール起草・コード生成・推論の説明）
2. **リストから選ぶ・スコアする・yes/no → Jev**（次のワーカー・関連性・準備完了・承認要否）
3. **正確なルール → コード**（10アクションで停止・$5上限・件数カウント・日付比較）

> 3つ目のバケットが予想以上に重要。**よく設計されたカスケードの最大の節約は安いモデルを使うことからでなく、安い決定がリクエストを plain code へルートしてモデルを完全にスキップする部分から来る**

## Step 2: 三つのプリミティブ

- **Choice**: 選択肢から1つ。**最大255オプション**（各数トークンなので短縮リストでなく全リストを渡す）。**必ず明示的な other を追加**（最も近い誤りを選ぶ代わりに「当てはまらない」と言える）。`.choice` `.probabilities` `.confidence` を返す
- **Score**: スペクトラム上に配置。2-10の順序付きレベルを言葉で記述。`.score`（1.035 のようにレベル間にも落ちる）
- **Noul**: yes/no を確率として。`.noul`（0-1）。「数字そのものが信念」なので confidence フィールドなし
- **Jev は質問のフィールド名を見ない**。要件は instructions と criteria の説明に書く。criteria は instruction の延長で、矛盾させない

## Step 3-4: 接続と最初の呼び出し

- `pip install typesafe-sdk`（Python 3.10+）/ `npm install @typesafe-ai/sdk`（Node 20+）。単一エンドポイント `POST https://api.typesafe.ai/v1/systemone`
- モデル版を明示的にピン（`jev-1.13.0`）。**jev-latest は新リリースで移動し、閾値を調整済みなら全決定が無言で変わる**
- state は文字列・JSON オブジェクト・メッセージ配列。コンテキスト制限: **state+全質問で64Kトークン、state+最長の1質問で32K**

## Step 5: Gate on Confidence（最重要パターン）

Jev は **RLCD（Reinforcement Learning for Calibrated Decisions）**で訓練 — 人間の選好でなく結果に対して確率を最適化。**confidence は集合的に意味を持つ**（高い confidence は本当に高い精度と相関）。

グローバル閾値でなく**アクション毎に、間違いのコストに応じてスケール**:
- confidence < 0.5 → 人間へエスカレート（常に）
- 読み取り専用 look up → 低いバーで実行
- **お金を動かす・送信・元に戻せない → 高いバー + 人間確認**

> 診断: `.probabilities` が全オプションでフラットなら、**与えた state から選択肢が区別できない**シグナル。モデルが混乱しているのでなく criteria が悪い

## Step 6: Ask Everything at Once

質問は並行実行なので、**10問目はトークンだけ費やし時間はほぼ増えない**。LLM で培った「まず安い呼び出し→必要ならフォローアップ」の直感が反転する。**全部前もって聞いて、コードに関連するものを決めさせる**。

- TypeSafe の cookbook: 13問のブリーフィングを1呼び出しにバッチ = **1問ずつより約12倍安く10倍速く、回答は同一**
- Browser Use デモ: 各ページ観測を番号付き要素テーブルにし、**操作と対象を同じ往復で**尋ね、選ばれた操作の分岐だけ実行。チューリッヒ→ロンドンを7.1秒・$0.0039（ページロード込み）
- 正確に言えば「フライト結果を見つけた。チケットは予約していない」

## Step 7: Build the Cascade

カスケード構造: 1つの分岐はモデルに触れない（純コード）。1つは専門 LLM。1つは人間へエスカレート。**「Jev はフロンティアモデルを置き換えるのでなく、どのリクエストがそれに値するかを決める」**

- 公開経済性の最も明確な実証: 1,018論文の要約に生成モデル $3.99、分類に Jev $0.08（中央値256ms/論文）。**「LLM を置き換えよ」でなく「各々をそのために使え」**

## The Failure Modes（出荷前に読む）

TypeSafe は "jaggedness" ページ（現行モデルの苦手を列挙）を公開 — 異例なほど正直:

1. **文字通りに読む** — 書いた質問に答え、意図した質問に答えない。否定・暗黙の条件は額面通り。「間違った回答を見て『本当はこう意味だった』と説明してしまう」= instructions の欠けている半分
2. **計算機でない** — カウントは信頼できず、対象が大きいほど誤差が増える。コードで反復し1項目1 Noul
3. **日付は順序量でなくテキスト** — 先後・間隔・ウィンドウ判定は信頼できない。抽出は列挙値の Choice で、順序と算術はコード
4. **Context rot が実在** — 質問に不要な材料で state が埋まると精度が落ちる。コードで先に検索・フィルタし、質問が実際に必要なフィールドだけ送る
5. **state 以外の世界知識なし** — 何も調べられない。state の組み立て側が Jev が知り得るものを決める。**弱いソースは悪い材料についての well-calibrated な判断を生む**
6. **state は敵対的として扱われない** — 自分の分類を主張するよう設計されたテキストが回答を動かせる。ユーザー制御コンテンツが state に入るなら、それが脅威モデル

運用: レート制限 250K tokens/s・1,200 req/min。**全決定でモデル版・確率・confidence をログ**。$0.0004/件の層でログが薄いと、300件の返金が間違ったキューに行った時に再構成不能

## The Honest Scorecard（バランスシート）

- TypeSafe 自身の4ワークフロー評価で Jev は **約67.8%** — ミッドティアフロンティアと同率、トップモデル（70%台前半）より下。ただし**約200分の1のコスト・50分の1のレイテンシ**
- 注意点4つ:
  1. **その列は精度でない** — ground truth なし。2つのフロンティアモデルの平均でコンセンサスラベルを作り、全員をそれで採点（2モデルとの一致度）。TypeSafe 自身が明記
  2. **自己運営** — TypeSafe がワークフロー設計・ハーネス構築・実行。独立再現なし。**自分のトラフィックで評価してから誰のベンチマークも信用するな**
  3. **「ハルシネーション不能」は語感より狭い** — スキーマ外の値は返せないが、**誤った妥当な値は返せる**。構造化出力0%エラーは構成による主張で、実測ではない
  4. **価格は動きうる** — 現行価格が補助金か社外からは分からない

## The Real Alpha

> **Let the LLM research, plan, and write. Let Jev route, score, approve, and escalate. Let code execute the decision and own anything irreversible.**

最後の節が他の2つと同じくらい重要: **較正済み confidence はより攻撃的にルートする根拠であって、元に戻せないアクションを発火させる根拠ではない。Prepare, then approve. Always.**
