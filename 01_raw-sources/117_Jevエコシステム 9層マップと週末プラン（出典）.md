# 原文（@hrswatigupta の X ポスト全文・構造化）

**What happened in the 7 days since launch, which of the 9 new layers are worth your time, and what to build first.**

2026-09-15 に TypeSafe AI は Jev を出荷（1単語も書けないモデル）。1週間後、**家系図**ができた: オープンクローン Laya・MacBook で訓練できる Kev・Apple Silicon ネイティブの laya-mlx・7秒でフライト検索するブラウザエージェント・Codex セッションの毎ターンにモデルを選ぶルーター・ローカル Jev 互換サーバー・31,500件の人手ラベル判定に基づく独立リーダーボード・macOS/Android/MuJoCo ドローン/Pokemon Red で走るコンピュータ利用実験。**先週ツールだった Jev は、誰も計画しなかったプラットフォームに見える**。

## 60秒リフレッシャー

- Jev: TypeSafe AI 初のモデル（2026-09-15・DCVC 主導 $40M シード）。創業者 Diogo Almeida は ChatGPT の背後の RLHF の共同発明者。**チャットモデルは人間が読んで楽しむテキストの生成に最適化。Jev はプログラムが分岐できる決定の生成に最適化**
- インターフェースは1リクエスト: **State**（文字列/JSON/テキスト配列）+ **型付き質問**（コードで定義・プロンプト文字列でない）→ **型付き回答**（各質問に1値+確率。テキストなし・JSONパースなし・説明なし・拒否なし）
- 3質問型: **Choice**（最大255オプション・全オプションの確率を返す）／**Score**（順序付きルーブリック・2-10レベル・期待レベルを返す）／**Noul**（yes/no 確率）
- エンドポイント: `POST https://api.typesafe.ai/v1/systemone`

## なぜエコシステムが形成されるか（モデル名でなく）

チャットモデルのローンチは「誰が最も賢いか」で競う。**決定モデルのローンチは「形（shape）」で競う**。Jev のリクエスト/レスポンス形は小さく再現可能で、「Jev-compatible」がすでに機能するラベル。形が安定すると3つの力:
1. **ロックイン恐怖**: ウェイト非公開・オンプレなし。ローカルフォールバックは nice-to-have でなく**リスク台帳の1行**（→Laya/Kev/互換サーバー）
2. **決定層はスタックのどこにも収まる**: 全エージェントに毎セッション数千の小さな選択（次のツール・ページ状態・diff は危険か・今ターンのモデル）。どれもテキスト生成不要（→ルーター/ブラウザエージェント/ガードレール）
3. **誰かが採点しなければならない**: evals は3日目に到着し、採用判断に最も重要な層

**採用数字**: Vercel によると Jev は AI Gateway 史上最速採用 — 24時間で有料チームの約13%（GPT-5.6 ファミリーの2倍超・Fable 5.1 の6倍超）。

## 9層マップ

| # | 層 | 代表 | 得られるもの |
|---|---|---|---|
| 1 | オープンクローン | Laya / Kev-0.5B/8B / Jevlike / OpenJev | 公開ウェイトの Jev 型モデル |
| 2 | ローカルランタイム | laya-mlx / jevmlx / Kev on Apple Silicon | クラウド呼び出しなしの sub-20ms 決定 |
| 3 | Jev互換サービス | LocalJev / openjev-sglang | 既存 Jev クライアントを localhost へ |
| 4 | ブラウザ+コンピュータ利用 | jev-ultrafast / jev-browser / typesafe-computer-use | アクションループ内の Jev |
| 5 | モデルルーター | jev-router / DSH Codex Router | 毎ターンの最安モデル+推論深度 |
| 6 | チャット+消費者アプリ | Needle / HA-Jev | UI の下の高速層としての Jev |
| 7 | Evals | jevals.com / JevBench | 人手ラベルの精度と較正 |
| 8 | SDK+グルー | 公式 Python/TS・Go・Swift・PHP・R・Elixir・MCP・SQL | 好きな言語から Jev |
| 9 | 本番統合 | Vercel AI Gateway / eve / LangChain / duckdb-jev | 既存システム内の Jev |

### Layer 1: オープンクローン
48時間で少なくとも6つ（Latent.Space 目録より）:
- **Laya**（Convai）: ModernBERT-large + PPO・421M（多言語+322M）・Jev 互換 API 形・ONNX/MLX ポート
- **Kev**（Jared Palmer / Cognition）: Qwen2.5-0.5B + LoRA・Apache-2.0・**MacBook Pro で訓練・実行**（M5 で自分とチェス）
- **Bespoke Nimble**: Qwen3.5-9B LoRA・データキュレーションで66%→90%
- **Jevlike**: 埋め込みのみ・**約40KB**（「決定」はどこまで小さくなれるかの床をテスト）
- ほか OpenJev（4B/35B）・NanoJev（0.6B・訓練パイプライン込み）

> シグナルの正しい読み方: 2日で6実装（40KB のおもちゃから 9B LoRA まで）は、**核心アイデア（小さいモデル・型付き出力・較正済み確率）が既存ベースモデルと既知の訓練法で再現可能**なことを意味する。TypeSafe の告発でなく要点: **カテゴリは誰でも実装できるアイデアで、実装品質に差がある**

正直なギャップ: Kev は MacBook で6問約160ms だが**ドメイン外では Jev に約19点差**（The Unwind 検証）。Laya の「Jev より50倍速い」は方法論非公開の単一 X ポスト（リポジトリ自身の 13.42ms@M3 Max は実在・再現可能だが hosted Jev との同条件比較は公開記録にない）。

### Layer 2: ローカルランタイム
目安: **決定が1Kトークンに収まり 20ms 未満が必要なら laya-mlx か Kev が候補。32K コンテキストや TypeSafe 級の較正が必要なら hosted API（か、より良いローカルチェックポイントを待つ）**。

### Layer 3: Jev 互換サービス
クローンは新モデル。**互換サービスは別の技: クライアント・SDK・コードを保持し上流だけ交換**。
- **LocalJev**（githubnext）: Bun/TS サーバーが Jev の `/v1/systemone` を実装し OpenAI 互換ローカルバックエンドへブリッジ。OpenAI API は logit 読み取りを公開しないため、決定リクエストを分類プロンプトに書き換え・JSON 確率出力をパース・不正応答でリトライ・Jev 準拠の choices/score/エントロピー信頼度へ正規化
- **正直言われた catch**: これは prompted JSON 確率出力であって Jev の直接 logit 方式でない。**本番で信頼する前に自分のデータで較正を確認**
- 使い方: `TYPESAFE_BASE_URL=http://127.0.0.1:8787` を上書きするだけ。**1日目から Jev API 形に対してクライアントを書けば、ローカル vs hosted の選択は環境変数になる**

### Layer 4: ブラウザエージェントとコンピュータ利用
- **jev-ultrafast**（Browser Use・MIT）: 毎ステップ原子 DOM スナップショットを読み、可視コントロールの**番号付きテーブル**を構築。Jev が1リクエストで2ヘッドをスコア: **操作ヘッド**（CLICK/TYPE_TEXT/SELECT/SCROLL/WAIT/DONE/BLOCKED）+ **対象ヘッド**（どの要素）。テキストモデルは TYPE_TEXT が選ばれた時だけ。**決定ループにスクリーンショットなし**
- 制限リストを読め: **DONE 決定は成功の証明でない（最終ページを別途検証）**。shadow roots/iframes/canvas/ファイルアップロード等は範囲外
- **jev-browser**（jkudish）: MCP サーバー+CLI+ライブラリ。Cline 公式プラグインコレクション入り
- rtrvr.ai 独立テスト: Jev オンで LinkedIn タスク31%短縮（95.5s→65.8s）・Amazon カート43%短縮。**0.95 信頼度の Click Send が効果を生まなかった時、盲目的リトライでなく LLM へ委任した**事例も記録
- おもちゃ層（パターンの一般化を最速で観察できる）: Super Mario Bros・Snake（1tick 1決定）・Pokemon Red・StarCraft・MuJoCo クアッドローター 2.5Hz・SO-101 ロボットアーム等
- **リアリティチェック**: OSWorld 2.0 で最良のフロンティア・コンピュータ利用エージェントも長期タスクの**20.6%** しか完了しない。**Jev はそれを直さない。直すのはエージェントループの最遅部（アクション毎のモデル呼び出し）をサブ秒の有界決定で置き換えること。完全自律が製品でない。エージェント内部の安く速い条件反射が製品**

### Layer 5: Codex ルーター（ルーティング全体）
最もクリーンなコスト話: コーディングエージェントの**毎ターン**がまず Jev を通り、3問に答える:
- **tier**（Choice）: 機械的ローカル/通常エンジニアリング/困難で高リスク。**Jev はモデル名でなく仕事の記述だけを見る**
- **effort**（Score）: どれだけ段階的推論が必要かの4レベル
- **risky**（Noul）: 本番/金/資格情報/元に戻せないものに触れるか
- (tier, effort, risky) をモデル+推論深度へ写像。**非対称閾値: 昇格は低いバー（0.3）・降格は高いバー（0.6）**。50%しか確信のない困難タスクを降格して金を節約しない
- **jev-router**（flaviusapop）: Claude Code/Codex/Grok CLI/opencode の毎ターンをルート。約300ms 追加。**制限: ルーティング決定のためにプロンプト本文が TypeSafe へ送られる（他は送らない）**
- 実例トランスクリプト: `jev: tier fast (0.87) - effort low (0.71) - risky 0.02 - 249ms`
- **なぜこのカテゴリが伸びる**: モデルルーティングはスタックで最もレバレッジの高いコスト統制で、**ルーティングは生成でなく決定**。Jev 以前はヒューリスティクスか JSON パースに包まれた安い LLM。今は較正済み信頼度を持ち100-250ms

### Layer 6: チャットと消費者アプリ
Jev はチャットできない。**「Jev チャットアプリ」= 会話 UI の下の高速層として Jev（intent/routing/triage/confidence）。LLM が全単語を書く**:
- **Needle**（The Unwind・Apache-2.0）: Cmd+F の新解釈。**意味で検索**。「キャンセルしたらどうなる?」と聞くと Jev がページのソース文をスコアし意図に合う通路を選択し元テキストでハイライト。Chrome 拡張+React プレイグラウンド
- **HA-Jev**: Home Assistant 統合。「玄関のドアは閉まってる?」が**チャット返信でなく確率**になる
- 設計問いはもはや「どの LLM」でなく「**会話ループのどの20個の決定を2秒でなく100ms で回せるか**」

### Layer 7: Evals（信頼すべきものを教える層）
- **jevals.com** は独立（TypeSafe 非提携）。**参照モデルでなく人間ラベルに対して採点** — ほとんどのモデルマーケティングがやらないこと。31,500決定・7モデル・3質問型（2026-09-18リリース）
- 3つの結論:
  1. yes/no と choice で **Jev は7モデル中 top-2 を価格の端数で**。速度・価格の売りは独立計測を生き残る
  2. **順序付きルーブリック採点では誰も当て推量を超えていない**。Jev の9.2が最高だが本番.ready でない
  3. **p95 レイテンシ 653-693ms が計画すべき正直な数字**（ローンチ投稿の70ms でない）
- 他のLLM: GLM-5.3 60.6/66.8・Qwen3.8 Flash 62.4・Mistral 58.0・Mercury 55.7・DeepSeek V4.1 Flash 47.5（Decision Score 0=基礎確率の当て推量）

### Layer 8/9: SDKと本番統合
- 公式 Python/TS に加え Go/Swift/PHP/R/Elixir・MCP サーバー・SQL 拡張
- 本番: Vercel AI Gateway・eve・LangChain ハーネス・duckdb-jev

## 週末プラン（初めての Jev 実験）

1. **候補は3特性**: よく呼ばれる・有界な選択肢・間違っても安い（サポート窓口振り分け/請求関連か Noul/エラーログの修正カテゴリ/草稿の品質ルーブリック/送信安全か Noul）
2. **質問を先に書く**。**悪い質問は実務で Jev が低パフォーマンスになる第1位の理由で、完全に自分で制御できる部分**。良い Noul は証拠を名指し（「既に支払った金の返金を要求しているか」）。悪いのは曖昧（「緊急か?」）。Choice の criteria はラベルでなく「何を探すか」の記述に
3. **呼ぶ**（curl/Python 例・timeout=2秒）
4. **閾値とエスカレーション経路を足す**。**較正済み確率が製品。生の回答ではない**: ≥0.85 自動ルート／≥0.60 ルート+レビュー抽出／未満 人間へ（当て推量しない）。**閾値は例からでなく自分のログから選ぶ。1日目から全決定の確率をログ**
5. **Mac ならローカルレーンを並行で**（kev クローン）

## ノイズの読み方
- 独立計測のない単一投稿の速度主張は未検証。リポジトリ自身の数字だけ再現可能
- 互換層は prompted JSON であって直接 logit でない
- 「70ms」は西海岸計測。p95 を計画に使え

## 来週やること
**1つの反復決定を選ぶ。測る。次を置き換える。** ルーターを1つの CLI に入れる・サポート窓口をルートする・Noul を既存ガードレールに足す。

## Takeaway
Jev は7日でツールからプラットフォームらしきものになった。**9層すべてが TypeSafe ではなくコミュニティから来た**。形（shape）が安定すれば、エコシステムが続く。
