# 本文（再構成・英語原文保持）

## なぜチームが単独ロングセッションに勝つか

単一チャットは**これまで読んだすべて**を抱える。すべての行き止まり、開いて捨てたファイル、誤った迂回がウィンドウに残り、本当に聞きたいことと注意を争う。

**サブエージェント**は独自のコンテキストウィンドウと独自のシステムプロンプトで走る。必要なものを読み、仕事をし、答えを返す。**ノイズはあなたの会話に一切触れない。**

> Two levels means the noise from the noise also stays away from you.（2レベルで、ノイズのノイズもあなたから遠ざかる）

Anthropic のネスト調整: 6月出荷の深さ5上限 → **7月21日に全面無効化** → 3日後に**デフォルト深さ3**で復帰。

## Phase 1: 最初のサブエージェント

**Step 1. 何を買うか理解する。** サブエージェントは「より長いプロンプト」ではない。**厄介なところへ送り出して、厄介さを回答と一緒に持ち帰らせないための、別のコンテキストウィンドウ**。

**Step 2. 1ファイル書く。** サブエージェントは `.claude/agents/` に frontmatter 付き markdown で置く:

```markdown
---
name: finder
description: Locates files and code relevant to a task
model: claude-sonnet-5
effort: low
tools: Read, Grep
maxTurns: 8
---

Find what was asked for. Report file paths and
three lines of context each. Never edit anything.
```

**Step 3. 最小の仕事を与える。** ファイル検索、チェック実行、ディレクトリ要約。**より大きいものを作る前に1回の完全実行を見よ** —— 何が、どんな形で戻るかをここで学ぶ。

## Phase 2: チームにする

**Step 4. タスクではなくワークストリームで分ける。** 「タスクごとにエージェントを spawn」は単にtodoリストの移動。**領域で分けよ**: API変更 / テスト / ドキュメント。各オーナーが自分の領域をさらに分割できる。

**Step 5. ファイルに触れないオーケストレーターを置く。** 仕事は分割・委譲・組み立てのみ:

```markdown
---
name: orchestrator
description: Splits large tasks and assembles results
model: claude-opus-5
effort: high
tools: Read, Grep, Agent
maxTurns: 30
---

Split the task into independent workstreams.
Delegate each one. Never edit files yourself.
Assemble the final answer from what comes back.
```

**Step 6. 役割ごとにモデルとeffortをルーティングする。** —— **これが金のレバー。** Opus 5 は 100万入力$5 / 出力$25（Fable 5 の半額）。effortダイヤルが第2の軸を与える:

```bash
export CLAUDE_CODE_SUBAGENT_MODEL=claude-sonnet-5
```

frontmatter で必要なものだけ昇格:
- **オーケストレーター**: Opus 5 / high effort —— その決定が下位すべてに伝播するから
- **ワーカー**: Sonnet 5 / low effort —— ファイル検索は機械的だから

> Running the whole tree at one setting is how a team gets expensive without getting better.（ツリー全体を1設定で走らせるのが、チームが良くならず高価になる道）

## Phase 3: 深さと制御

**Step 7. ワークストリームが2度分割する時だけ中間層(lead)を置く。** lead は領域を端から端まで所有し、機械的部分を委譲する。**lead が受け取ったのと同じ曖昧さをそのまま下に渡すなら、その lead は不要。**

**Step 8. 構造的に深さをキャップする。** ワーカーの tools から **Agent を削除**。そのツールのないサブエージェントは、グローバル設定が何と言おうと何も spawn できない。環境変数 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` は**安全網であって設計ではない**。

> 罠: spawn 可能エージェントを制限する allowlist 構文は、エージェントが**メインスレッドとして走る時のみ適用**される。ネスト定義内では**暗黙に無視される**ので、安全境界として頼るな。

**Step 9. すべてに上限を置く。** 全定義に `maxTurns`。天井のないワーカーは、他の何かが止めるまで行き詰まりタスクでループする。機械的仕事には8ターン、オーケストレーターには30。

## Phase 4: 品質と規模

**Step 10. 仕事をしなかった検証器を置く。** 作った者が自分を採点することはない。**元の要件に対して出力をチェックする別役割**が、どれほどプロンプト調整しても捕まらない種類のエラーを捕らえる:

```markdown
---
name: verifier
description: Checks work against the original requirement
model: claude-opus-5
effort: medium
tools: Read, Grep, Bash
maxTurns: 10
---

Compare the result against the requirement, not against
what looks reasonable. Report pass, fail, or unclear
with the specific evidence for your verdict.
```

**Step 11. 1回の完全実行を見る。** stream-json モードで `--forward-subagent-text` を使うと、ネストされたサブエージェントが spawn 元に紐付いて出力に現れる。さもないと**深い作業は終わるまで不可視**で、時間とトークンがどこへ行ったか何も学べない。

**Step 12. チームを刈り込む。** ほとんどのタスクは3階層でなく**2階層**で十分。真の価値を出すチームは:
- ほとんどの日: オーケストレーター + ワーカー
- タスクが真に2度分割する時だけ lead を追加
- 高価なモデルは**最上位のみ**

> Depth 3 is a ceiling, not a target.（深さ3は天井であって目標ではない）

## よくある間違い

- **2階層の仕事に3階層を構築する** —— 余分な層はプロンプトオーバーヘッドと引き継ぎロスを無駄に加える。機能が存在するからではなく、**仕事が要求する時にleadを追加**
- **1モデル・1effortをどこでも** —— ファイル検索にオーケストレーター料金を払い、チーム構造の節約が消滅
- **ワーカーのtoolsにAgentを残す** —— 1つの曖昧な指示で、葉ノードが予定しない子をspawn。**構造的制限が設定に勝る**
- **検証器なし** —— ワーカー出力をチェックせず転送するleadは、leadでなく中継。検証こそがその役割の存在理由
- **完全実行を一度も見ない** —— チームは**引き継ぎで静かに失敗**する。見たことのないものは直せない

## 20分セットアップ

1. ワーカーファイルを1つ書き、実際の検索タスクで実行（6分）
2. tools に Agent を持つオーケストレーターを追加（5分）
3. サブエージェントモデル環境変数を安いデフォルトに設定（2分）
4. ワーカーから Agent を削除し深さを2にキャップ（1分）
5. `--forward-subagent-text` で1つの実際タスクを実行し、トレース全体を読む（6分）

> The upgrade isn't more agents. It's that the expensive model finally spends its tokens on decisions instead of file lookups, and everything noisy happens somewhere you never have to read.（アップグレードとはエージェントを増やすことではない。高価なモデルがついにファイル検索でなく**決定**にトークンを使い、厄介なことはすべてあなたが読まなくていいどこかで起きること）
