# 講演内容（主題別再構成・日本語）

## 進化の3段階
1. **Message AI**: トークンイン・トークンアウト（素のモデル）。だが複雑なエージェント/ループ/ワークフローになると、**エージェントループ・コンテキスト管理・ツール実行・セッション状態復旧・認証・観測性・カスタムツールロジックは全部自作**
2. **Claude Code → Agent SDK**: エージェントループのハーネス・コンテキスト管理・組み込みツール実行・サンドボックス・ファイルシステムを提供（裏側は Message AI）。**ホスティング・スケーリング・セッション状態・観測性はまだ自作**
3. **Claude Managed Agents**: **タスクと設定とカスタムツールロジックだけ持ってくれば、目的構築ハーネス・ツールランタイムサンドボックス・セッション永続化とチェックポイント・認証・クレデンシャルボールト・ホスティング・スケーリング・観測性は全部面倒を見る**。「プロトタイプに数時間→本番に数週間」の数週間部分を削る

## 3つのリソース
1. **エージェント設定**（ペルソナ/モデル/プロンプト/ツール/MCP・**バージョン管理されロールバック可**）
2. **インフラとガードレール**（コンテナ・ネットワーク境界・許可ホスト等の環境）
3. **セッション**（設定+環境から起動）

## キーアーキテクチャ変更: 脳と手の分離
- 従来: エージェントループとツール実行が**同一コンテナ**→起動のたびに高レイテンシ・単一障害点
- Managed Agents: **ループ（脳）とサンドボックス（手）を分離**。**全ユースケースがサンドボックスを必要としない**→必要な時だけ起動。**スケール・低レイテンシ・高信頼**

## SRE エージェントの実装例
インシデント（チェックアウトサービス高負荷）→ エージェント定義を書く（クラウドに永続化）→ コンテナ/ネットワーク境界を定義 → ログファイルやスキルをマウント → セッション開始 → **本物のサンドボックスで grep/glob し根本原因を調査**。**このコードはそのまま本番グレード**（同一 agent ID/環境で製品に組み込み）

## 運用モデル
- **会話はクラウドに存在**。ラップトップを閉じてもエージェントは動き続ける。イベントで方向を制御
- **マルチセッション永続化**・セッション一覧
- **階層メモリ**: セッションから学習し時間と共に記憶
- **dreaming**: トランスクリプトから学習しスキルを実装・メモリストアを改善
- **outcomes**: 成果物を複数回反復（Ralph ループ的な）し高品質出力
- **vaults**: クレデンシャルの安全な保管
- **MCP サーバー/ウェブフック/権限ポリシー/インタラプト**
- **コンソールのエージェントビルダー**: 平文で欲しいエージェントを記述すると本番グレード設定を生成
- **scheduled/triggered agents**: 毎朝8時のダイジェスト等 cron 的に実行
