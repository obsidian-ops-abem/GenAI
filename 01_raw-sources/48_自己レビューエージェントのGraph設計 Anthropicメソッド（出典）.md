# 本文（再構成）

## 導入: エージェントは馬鹿ではない。形が間違っている

短いタスクは動く。だが40ファイル横断のリファクタ・マイグレーション・1時間走る調査となると、ドリフトする。20分前の決定を忘れる。1つのファイルを直して別のを壊す。**モデルのせいにしたくなるが、通常モデルは正常。ワークの形が間違っている。**

## Loops and graphs

ほとんどのエージェントはループ。制御はモデルの中にある。40分目に失敗したとき、何分目に間違えたか分からない。

**グラフは制御をモデルの外に移す。** ステップ・接続・state の居場所を定義。モデルは依然思考するが、あなたが描いたノードの中で。

4つの変化: (1) **失敗場所が見える**（名前付きノードで失敗） (2) **再開できる**（state は文脈窓でなくディスク） (3) **独立ブランチを同時実行** (4) **退屈な部分を決定論化**（モデルに推測させない）。

## This is not theory（実証例）

- **Anthropic**: 先月10コードパッケージをこの方法で移行
- **Jarred Sumner**: Bun を Zig→Rust に移植。**2週間弱で100万行**、既存テストスイート全通過・CI。事後19回帰、全修正。Rust 版は6月に Claude Code 内に shipped。**59億 uncached 入力トークン・6.9億出力トークン消費（API価格で約$165,000）**。無料の技法でない —— $300万・4年のプロジェクトを2週間にする技法
- **Mike Krieger**: Python コードベースを週末で **165,000行 TypeScript** へ。数百エージェント・**8フェーズゲート**・**3ラウンド adversarial review**・最終チェック（全コマンド出力を Python 原典と diff）

> 両エンジニアとも自分のセットアップを「グラフ」と呼ばなかった。キュー・ゲート・レビューア・デーモンと描写した。**それはグラフだ、図でなくスクリプトで描かれた。**

## 唯一の原理

> **Anthropic**: コードを直すのではない。**コードを生んだプロセスを直す。**

レビューアが3番目のファイルで同じミスを捕らえたとき、3ファイルを直すのは間違い。**ルールに1文追加してバッチを再生成**。個別の失敗はループの仕事。あなたの注意はパターンへ。

## 8ステップでグラフを構築する

全て1フォルダに置く: `mkdir -p agent/{source,output,rules,scripts,logs}`

### Step 1. 判定器（judge）を最初に構築する
終了条件のないエージェントは決して終わらない。「完了した気がする」は条件でなく気分。`scripts/judge.sh` を作る —— 1ファイル取り exit code 0/1 を返し理由を出力。コードならテストランナー、文書なら必須セクション/禁止パターン、データなら schema/行数。**出力を開かずに「どのコマンドが合格を教えるか」に答えられたら judge がある。**

### Step 2. 判定器をわざと壊す
**絶対失敗しない判定器は装飾品。** 既知の良好ファイルを壊したコピーで FAIL が出るか、良好版で PASS が出るかを両方向検証。Anthropic も両方向で validate（原典で通過確認＋わざと壊したコードで失敗確認）。スケール生成の前にやる。

### Step 3. ルールブックを書き、絶対にその周りをパッチしない
`rules/rulebook.md`。全ワーカーが触る前に読む。曖昧さを Claude と声に出して話しながら構築 —— 「well, in that case it should probably...」と思ったとき、それがルール。**2つの性質**: (a) 成長する（全レビューアキャッチが新たな1文に） (b) 何もバイパスしない（出力を手編集した瞬間、2つの真実源があり片方はあなたの頭の中）。

### Step 4. 3アイテムでルールをストレステストし、成果を削除する
ルールブックあり/なしで3アイテムを2通り実行し diff。**全差分は、ルールが間違っている/欠けている/モデルのデフォルトより悪い場所。** ファイルでなくルールブックを直す。**成果は全削除** —— 目的は3ファイルでなくルール。Jarred はこの段階で **1,448ファイル全に伝播したはずの2つの重大問題**を捕獲。

### Step 5. state をディスクに、文脈窓でなく
`scripts/queue.sh` が**ファイルシステムから毎回ワークキューを再構築**。キューに関する何も会話に住まない。出力ファイルが存在するかで「完了」を判定。**プロセスが構造的に再開可能** —— 60%で殺し再起動すれば60%から再開（ディスクが覚えている）。

### Step 6. お互いを見られない2人のレビューアを使う
同じ文脈のレビューアはワーカーに同意する（推論を見て前提付けられている）。**各アイテムに2つの新規セッション** を走らせる。各レビューアは出力とルールブックのみを見る（ワーカー推論もチャット履歴もなし）。

> **全発見にルール引用を強制する**のがループを閉じる詳細。引用が曖昧な不満をキューアイテムに変える。**3ファイルにわたり3回引用されたルールは、3つの問題でなく1つの悪く書かれたルール。その行を書き直して該当バッチを再実行。**

2人のレビューアの不一致は通常、その場所でルールブックが曖昧なことを意味。コイントスでなく編集。

### Step 7. 退屈なチェックを決定論化し、コストで配置する
スクリプトで検証できるものをモデルで検証すべきでない。**チェックの周波数をコストに合わせる**:
- **高速チェックはループ内**: judge をワーカー呼び出しに直接。Mike は TypeScript コンパイラを全ユニットで（秒で返る）
- **低速チェックはループ外・バッチで**: キュー全体を終えてから高価なチェックを1回。Jarred は cargo が分単位のためコンパイラをループから完全追放、ワークスペース全体で1回走らせエラーリストに対し fixer エージェントを並列 dispatch

> `uniq -c | sort -rn` が個別エラーでなく**カテゴリ**を見せる。Jarred は Zig が許容していた cyclic import から何千もの Rust モジュールエラーにヒット。修正は何千個でなく、**1つの分類ルールをループに追加**することだった。

### Step 8. 高価な操作を直列化する
1つの操作がコスト/時間を支配するなら、全エージェントにトリガーさせない。エージェントは操作を実行するのでなく**ディレクトリに要求を書く**。単一デーモンが所有し、バッチ全体で1回再構築。Anthropic 版はビルドデーモン（バイナリを再構築できる唯一のプロセス）。**10エージェントがそれぞれ完全再構築をトリガー = 1つにバッチ化できる作業に10倍支払う。**

## 役割でモデルを選ぶ
最大モデルを至る所で走らせない。Mike は主力移行で **Sonnet で12サブエージェントを fan-out**。大きなモデルは2ジョブに温存: **レビューア**と**他エージェントが従うルールを書くもの**。悪いルールは全下流出力に伝播 —— まさに能力に金を払う価値がある場所。

## いつやるべきでないか

グラフは**開始前にワークの形を知っている必要がある**。それがトレードオフ全体。スキップすべき場合:
- **タスクが1回しか走らない**: 全セットアップは反復に償却される。11ファイルのために judge とルールブックを構築するのは11ファイルをやるより遅い
- **ステップがまだ分からない**: 研究・不慣れなデバッグ・見たことのないコードベース探索。ループはあなたが描かなかった道を見つける。トポロジーを早く固定すると、ワーク内容に関する間違った推測を固定するだけ
- **機械的 judge がなく、あり得ない**: 正確さが本当に各アイテムであなたのセンスを必要とするなら、スクリプトはあなたを置き換えず、レビューアノードは演劇になる
- **中間の道**: まずループを走らせて形を学び、全修正をメモする。そのメモが最初のルールブック。2回目の実行にグラフを構築する。

## 実際のシフト

> 問題は決してモデルが十分賢いかでなかった。**次に何が起きるかを誰が決めるか。** ループではモデルが決め、最後に分かる。グラフではあなたが事前に決め、モデルが描いた境界内で実行する。

Anthropic の9語: **you do not fix the code, you fix the process that produced the code.**

100万行の移行が印象的なのは、モデルが100万行を書いたからでない。**40万行目で何かが悪くなったとき、悪くなった名前付きの場所があり、それを直すことが1文を編集してバッチを再実行することを意味したから。**
