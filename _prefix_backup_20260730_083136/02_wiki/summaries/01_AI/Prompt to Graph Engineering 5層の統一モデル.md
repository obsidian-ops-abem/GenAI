# Prompt to Graph Engineering: 5層の統一モデル

> [!info] 出典
> Akshay Pachaar（@akshay_pachaar）、2026年7月26日21:30公開（Xポスト）
> [元投稿](https://x.com/akshay_pachaar/status/2081356379026280677)
> 詳細メタデータ: [[Prompt to Graph Engineering 5層モデル（出典）]]

プロンプトエンジニアリング → コンテキストエンジニアリング → ハーネスエンジニアリング → ループエンジニアリング → グラフエンジニアリング、という5つの用語は互いを置き換えるものではなく、**それぞれが前の層を包み込む入れ子構造**だ、という整理。このボルトに既にある [[_prefix_backup_20260730_083136/02_wiki/summaries/01_AI/LOOP vs GRAPH vs HARNESS ENGINEERING]]・[[Graph Engineering エージェントを行列から解放する]]・[[ループエンジニアリング14ステップ]] を1つのフレームにまとめる、いわば索引的な内容。

各層を区別する最もクリーンな方法は「**1つの作業単位がどんな形をしているか**」を問うこと。

## 5層と作業単位

| 層 | 一言 | 作業単位 |
|---|---|---|
| Prompt engineering | メッセージ | 1つの入力 |
| Context engineering | 記憶 | ウィンドウに残るもの |
| Harness engineering | 機械 | マシンを通る1回の通過 |
| Loop engineering | 実行 | 全体の実行 |
| Graph engineering | 協調 | 全体の仕事 |

## 各層の説明

**Prompt engineering = メッセージ**
呼び出しの前にモデルは何も覚えていないので、プロンプトが必要な全宇宙（役割・背景・指示・例・フォーマット）を運ばなければならない。出力が不十分なときのスキルは、どの成分が失望させたかを特定することであり、毎回指示を丸ごと書き直すことではない。

**Context engineering = 記憶**
多くのステップにわたるとウィンドウは有限だが利用可能な情報は無限なので、キュレーションを強制する。キュレーターは重要なものを保持し、有用だがかさばるものを圧縮し、残りは捨てる。良いキュレーションとは主に「何を捨てるか」を知ることであり、もっと詰め込むことではない。

**Harness engineering = 機械**
単独のモデルはただテキストを生成するだけ。ハーネスは必要なものを集め、実行し、ツールやサブエージェントを呼び出し、テストやジャッジで結果を検証する。その検証ステップこそが「APIを呼ぶこと」と「エージェントを走らせること」の決定的な違い。

**Loop engineering = 実行**
1回の通過で仕事が終わることは稀なので、何かがマシンをもう一度実行するかを決めなければならない。その決定には、事前に定義された目標、最大反復回数や予算上限のようなブレーキ、そして感覚ではなく自動化された完了チェックが要る。ツールを求めなくなったエージェントは「ターン終了」だが、それは「タスク完了」と同じではない。

**Graph engineering = 協調**
複数のループが協力する必要が出てきたら、何がいつ実行されるか、何が並行して実行されるか、誰が誰をチェックするかを指定しなければならない。ノードが作業をし、エッジが次に何を実行するかを決め、共有状態がそれらの間を流れる。単一のループは、自分自身を指すエッジを持つ1ノードのグラフに過ぎない——だからグラフはループを**置き換える**のではなく**統治する**。

## 統合の仕方

プロンプトとコンテキストは、どちらもハーネスの「収集ステップ」の内側に生きる。ハーネスは1回の通過であり、ループはその通過をもう一度実行するかを決め、グラフはどのループが実行されるかを決める。ズームアウトすると作業単位は大きくなり、ズームインするとプロンプトに戻る。

## デバッグへの含意

この階層構造は、どこを直すべきかも教えてくれる——「作業単位が壊れたレイヤーを見つけ、そのレイヤーを直す」。プロンプトは最も編集しやすいレイヤーなので、**本当は3層上（Loop/Graph層）の失敗の責任を、プロンプトが負わされ続ける**という指摘が刺さる。うまくいかないとき、まずプロンプトを書き直したくなるが、実際にはハーネスの検証ステップやループの停止条件、グラフのルーティングが壊れている場合が多い、という警句。
